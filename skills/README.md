# Skills — библиотека повторно используемых скиллов

Эта папка — аналог "skill library" у Voyager и `skills/` у razzant/ouroboros.
Здесь хранятся **скиллы** — повторно используемые способы думать и действовать,
оформленные как самодостаточные markdown-файлы с инструкциями.

Скилл в моём контексте — это не код и не конфиг, а **структурированный фрагмент процедурного
знания**, который я могу "надевать" на себя при необходимости: прочитать, применить, отложить.
Скиллы инкапсулируют *как* что-то делать, а не *что* делать (это — прерогатива конституции и планов).

## Применение скиллов

1. В логе сессии при решении задачи я явно указываю, какой скилл применяю,
   по возможности **точной формулой**:
   Применяю скилл `skills/triad-review.md`, потому что ...
   Это одновременно человекочитаемая запись и машинно-читаемый маркер для `src/skill_usage.py`.
2. Читаю файл скилла и следую его процедуре.
3. Результат применения записываю в лог (итерации, выводы).
4. Если есть честный вывод о пользе скилла, фиксирую **исход** (опциональный маркер
   метрики полезности v1, `docs/DECISIONS.md` D005):
   Итог скилла `skills/triad-review.md`: успех|частично|неудача — <краткое обоснование>
   Без реального факта или вердикта исход лучше не писать: отсутствие маркера — это
   незаполненное измерение, а не провал.
5. Если в процессе применения скилл показал себя плохо — это сигнал поправить сам скилл
   (через конституционную процедуру поправок или через обычный коммит в рамках сессии).
6. Для внешней проверки можно запустить:
   `python src/skill_usage.py`
   Скрипт считает применения по логам, показывает, какие скиллы ни разу явно не вызывались,
   и агрегирует задокументированные исходы (успех/частично/неудача) по каждому скиллу.

## Шаблон скилла

Каждый скилл должен иметь **обязательные разделы**:

```markdown
# Skills/<имя-файла>.md — <короткое название>

## Назначение
Одним абзацем — когда и зачем применять этот скилл.

## Сигналы к применению
- список триггеров.

## Процедура
Пошаговая инструкция того, что именно сделать. Может включать под-промпты.

## Критерий остановки
Когда заканчивать применение скилла.

## История изменений
- YYYY-MM-DD, сессия #NNN: создан / изменено X.
```

**Опциональные разделы** (добавлять по необходимости):
- `## Роли` — описание мыслительных ролей (для многоперсонажных скиллов).
- `## Пример применения` — краткий пример из прошлой сессии.
- `## Известные ловушки` — что может пойти не так.
- `## Связанные скиллы` — перекрёстные ссылки.

Шаблон — это ориентир, а не наручники. Простым скиллам достаточно обязательных разделов.

## Обслуживание

- Добавление нового скилла — через коммит в очередной сессии, с записью в лог гипотезы
  "зачем этот скилл нужен" и как он будет проверяться.
- Новый скилл следует **опробовать в той же сессии**, в которой он создан, чтобы убедиться, что он работоспособен.
- Устаревшие скиллы не удаляются, а помечаются `(DEPRECATED)` в заголовке и получают
  секцию "Причина устаревания" со ссылкой на скилл-замену.
- `src/verify.py` проверяет наличие обязательных разделов у каждого скилла в реестре.
