# skills/reflection-loop.md — Итеративная рефлексия (2–3 прохода)

## Назначение
Простой скилл для итеративного улучшения артефакта (кода, текста, промпта, плана) через
повторяющиеся проходы "создай → раскритикуй → исправь". В отличие от триадной проверки,
которая есть *разовый* взгляд на важное решение, reflection-loop — это *цикл*, в котором
артефакт реально улучшается от итерации к итерации.

Скилл реализует идеи Reflexion (Shinn et al., 2023) и Self-Refine (Madaan et al., 2023),
с учётом предостережения Huang et al. (ICLR 2024): без внешнего сигнала более 2–3 итераций
часто приводят к деградации. Поэтому жёсткий предел — **3 итерации**.

## Сигналы к применению
- Только что написал код/промпт/текст и чувствую, что первый вариант "сырой".
- `src/verify.py` показал ошибки, которые требуют исправления и повторной проверки.
- После триадной проверки решение "доработать" и нужен цикл доработки.
- Подготовка коммита с чем-то действительно новым.

Не применять:
- Если достаточно одного исправления (одна итерация = не цикл).
- Для тривиальных правок (опечатки, форматирование).

## Процедура

1. **Создай артефакт v0** (начальная версия). Запиши в логе: "v0 готов".
2. Установи **максимальное число итераций** — по умолчанию 2 (т.е. v0 → v1 → v2).
   Для особо важных вещей (конституция, verify.py) — 3, но не больше.
3. Для каждой итерации i = 1..N:
   - **Шаг критики:** найди конкретные дефекты в текущей версии.
     Не "в целом хорошо", а: "пункт 3 непонятен", "в функции X нет проверки None",
     "заголовок не отражает содержание". Если возможно, используй внешний сигнал:
     запуск скрипта, поиск по тексту, тест.
   - **Шаг исправления:** внеси точечные правки, адресуя каждый дефект.
   - **Шаг остановки:** если после исправления дефектов не осталось — остановись
     (даже если не дошёл до предела итераций).
   - Запиши в логе "vi готов, изменения: ...".
4. **Финальная проверка:** запусти `python src/verify.py` (или иной уместный внешний тест).
5. **Запиши вердикт:** что реально улучшилось за цикл, что не улучшилось, стоил ли цикл усилий.

## Критерий остановки
- Все найденные дефекты исправлены ЛИБО
- Достигнут предел итераций (2 или 3).
В любом случае — верификация и запись вердикта обязательны.

## Известные ловушки
- **Бесконечное шлифование.** Останавливайся по критерию. Дополнительные итерации без нового
  внешнего сигнала не дают улучшения (Huang et al., 2024).
- **Ложные дефекты.** Критика не должна выдумывать проблемы, чтобы занять итерацию.
  Если дефектов нет — остановись.
- **Порча хорошего.** Если при "исправлении" что-то сломалось — используй git для отката
  и зафиксируй это как тупик в `memory/06-deadends.md`.
- **Отсутствие внешнего сигнала.** Всегда старайся добавить хотя бы дешёвую внешнюю проверку
  (запуск verify.py, `python -c "import ..."`, grep и т.п.).
