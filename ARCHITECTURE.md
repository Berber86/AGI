# ARCHITECTURE — Emoji Wasteland Arena

## Статус документа

- Версия: 0.2
- Дата: 2026-07-29
- Сессия: 2

## Цели архитектуры

1. Статический сайт без бэкенда и базы данных.
2. Быстрый деплой на Vercel в бесплатном режиме.
3. Чистая игровая логика, которую можно unit-тестировать без DOM.
4. Простая структура, подходящая для итераций независимых ИИ-сессий.
5. Минимум зависимостей и отсутствие внешних графических ассетов.

## Выбранный стек

- **Vite** — сборщик и dev-сервер для статического фронтенда.
- **TypeScript** — строгая типизация правил игры и состояния.
- **Vitest** — unit-тесты для чистой игровой логики.
- **HTML/CSS/DOM** на старте — без тяжёлого UI-фреймворка.
- **GitHub Actions** — запланированный CI для тестов и production-сборки; workflow временно не коммитится, пока у GitHub App нет права `workflows`.
- **Vercel** — статический деплой из `dist`.

## Почему без React/Vue/Svelte на старте

MLP — это компактная пошаговая игра, где главная сложность в правилах, состоянии
и читаемом рендеринге сетки. UI-фреймворк можно добавить позже, но сейчас он
увеличит объём шаблонного кода и решений. Чистый TypeScript + DOM позволит
быстрее выделить тестируемое ядро.

## Архитектурные принципы

### 1. Чистое ядро игры

Игровые правила должны быть функциями вида:

```ts
nextState = applyPlayerAction(state, action);
```

Такие функции не читают DOM, не используют `Math.random()` напрямую и не зависят
от времени. Это позволит тестировать поведение врагов, урон, победу и поражение.

### 2. Детерминированная случайность

Когда появится генерация арены, она должна принимать seed/RNG-объект. Это важно
для воспроизводимых тестов и баг-репортов.

### 3. Тонкий слой рендера

Рендер получает готовое состояние и превращает его в DOM. Он не должен принимать
решения о правилах игры.

### 4. Состояние без скрытых глобальных мутаций

На старте допустима простая immutable-модель: действие возвращает новый объект
состояния. Если производительность станет проблемой, можно оптимизировать позже.

### 5. Доступность с первого экрана

Даже эмодзи-игра должна иметь:

- читаемые подписи;
- управление клавиатурой;
- контрастный интерфейс;
- текстовый журнал событий.

## Деплой

Vercel должен выполнять:

```bash
npm ci
npm run build
```

Результат сборки лежит в `dist`. `vercel.json` явно фиксирует `buildCommand`,
`outputDirectory` и `framework`, чтобы не зависеть от автоопределения.

## CI

CI через GitHub Actions запланирован, но файл `.github/workflows/ci.yml` временно не
лежит в репозитории. Причина: текущий GitHub App в Arena не имеет permission
`workflows`, поэтому GitHub отклоняет push коммитов, которые создают или меняют
workflow-файлы.

Когда права будут выданы, нужно добавить workflow, который запускает:

1. `npm ci`;
2. `npm test`;
3. `npm run build`.

До этого самопроверка выполняется локально этими же командами.
