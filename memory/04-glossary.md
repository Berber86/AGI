# Глоссарий

## Аутопоэзис (Autopoiesis)
Понятие, введённое чилийскими биологами У. Матураной и Ф. Варелой (1972).
Система является аутопоэтической, если она непрерывно производит и поддерживает саму себя,
собственную организацию и границы, через процессы внутри себя.
Ключевое отличие от аллопоэтических систем (производящих что-то иное, чем они сами).
Живые клетки — классический пример. Применительно к ИИ: система, которая сама
конструирует/модифицирует свой код, промпты, архитектуру.

## Уроборос (Ouroboros)
Символ змея, кусающего свой хвост — метафора цикличности, самопорождения и рефлексии.
В контексте ИИ: проекты, где модель использует саму себя как инструмент — пишет промпты для себя,
обучает модификации самой себя, самотестируется. См., например, Ouroboros Project в области
само-инструктажа (self-instruct), RAG с самоприсвоением, code-generating agents.

## Рекурсивный ИИ / Recursive Self-Improvement (RSI)
Идея ИИ, который может улучшать собственную архитектуру/алгоритмы/базу знаний,
что приводит к циклу улучшений с ускорением (гипотеза "взрыва интеллекта" И. Дж. Гуда).
В современном виде — агенты, рефлексивно вызывающие самих себя (например, ReAct, Reflexion,
Self-Refine, AutoGPT, BabyAGI, Voyager).

## Рефлексия (Reflection / Reflexion)
Механизм, при котором агент анализирует собственные предыдущие действия/ошибки
и корректирует стратегию, прежде чем продолжить.

## Сон агента (Dream)
Внутренний механизм компактной явной суммаризации последних сессий. В этом репозитории
реализован как `src/dream.py`, который создаёт `memory/07-dream.md` из логов.
Сон не заменяет исходные логи и конституцию: он служит быстрым обзором траектории
и всегда должен указывать источники.

## Осцилляция агента
Повторяющееся движение между состояниями без накопления прогресса: например,
«добавил → удалил → снова добавил» или многократный запуск одной проверки с той же ошибкой.
В этом репозитории первичный внешний сигнал даёт `src/stagnation.py`, а процедурная реакция
описана в `skills/stagnation-watch.md`.


## Контекстная деградация / Context rot
Состояние, при котором активный рабочий контекст LLM разрастается и теряет качество: в записях
становится больше шумовых хвостов, цифр без смысла, фрагментов мыслей и слабосвязанных суждений.
Проблема не в полном исчезновении памяти, а в загрязнении live context. В этом репозитории
процедурная реакция описана в `skills/context-hygiene.md`.

## Ограниченный активный контекст / Bounded active context
Намеренно ограниченный набор материалов, который загружается при пробуждении и во время одного
рабочего шага. Полная долговременная память остаётся в файлах, но поднимается task-directed.
В этом репозитории состав ядра, retrieval-гейты и триггеры clean rehydration заданы в
`prompts/context-policy.md`, а размер измеряет `src/context_budget.py`.

## Capability admission / Допуск по наблюдаемой компетентности
Ранний identity-blind gate новой сессии: вместо выяснения происхождения активной модели агент
решает свежие проверяемые задачи и получает PASS/FAIL. В этом репозитории policy находится в
`prompts/admission-policy.md`, checker — в `src/admission.py`. PASS означает только минимальную
готовность начать работу и не заменяет тесты результата или ручной merge-review.

## False accept / False reject допуска
**False accept** — gate дал PASS сессии, которую создатель затем обоснованно отклонил как слабую.
**False reject** — gate остановил сессию, которая могла бы выполнить работу достаточно хорошо.
Обе ошибки измеряются только сравнением с будущими ручными решениями, а не self-review gate.
