# Решения, принятые самостоятельно

Формат: контекст → решение → обоснование. Дополняется по мере работы над фазами.

## Фаза 0

### D-01. Репозиторий переименован концептуально, но не физически
Проект живёт в репозитории `Berber86/AGI` — название на GitHub Pages-URL зависит от
имени репозитория. Переименование репозитория не входит в полномочия агента;
везде в коде и документах проект называется **Cog Empires**.
*Если владелец переименует репозиторий в `cog-empires`, нужно поменять только BASE_PATH в CI — он берётся из `github.event.repository.name` автоматически.*

### D-02. Старое содержимое (Python-агент) удалено одним коммитом
По явному запросу владельца. История сохранена в git — восстановимо в любой момент.

### D-03. Прототип-референс отсутствует → движок написан с нуля по брифу
Приложение с HTML-прототипом было удалено владельцем («чтобы не быть ограниченным в
фантазии»). Все числа формул вынесены в константы (`COMBAT`, `RARITY_WEIGHTS`,
`CRAFT_COST_ORE`) — баланс правится в одном месте и легко фиксируется тестами.

### D-04. Случайность — только через явный RNG (mulberry32)
Никакого `Math.random` в `engine/` и `data/`. Бой детерминирован по seed: одинаковый
вход → побитово одинаковые события. Это база регрессионных тестов, реплеев и
будущего сервера.

### D-05. Поле 10×20 представлено 5 линиями × 10 колонок на сторону
По брифу сетка «есть», но геймплейно это 5 линий. 2 ряда на линию — визуальный
запас для будущей фазы расстановки; таргетинг использует только линию и колонку.

### D-06. Вражеские рекруты живут в общем пуле
Волки/скелеты/огры/лич — обычные `RecruitDef` с пустой стоимостью; флаг «игрочисти» —
константа `PLAYER_RECRUIT_IDS`. Меньше дублирования, единая формула расчёта.

### D-07. Догмы активируются только иконками технологий
В Innovation символы приходят с карт; здесь — с технологий. Постройки и рекруты
иконок не дают, чтобы дерево технологий оставалось главным источником «комбо».

### D-08. UI — один боевой оверлей с событийной лентой
Симуляция возвращает все события сразу; UI проигрывает их по таймеру (1×/2×/мгновенно)
и восстанавливает состояние чистой функцией `displayState(result, frame)`. Так реплей,
лог и анимации не могут разойтись друг с другом.

### D-09. Сохранение — автоснапшот всего GameData при каждом изменении
JSON в localStorage. Дёшево при текущих объёмах (десятки КБ), зато нулевой шанс
рассинхрона частичного сохранения. Версия схемы уже в поле `version`.

### D-10. Тесты — на чистый движок, не на React
49 тестов покрывают детерминизм боя, все ключевые механики, экономику, лут и сеты.
UI тестируется вручную на этом этапе (критерий — плейтест).

### D-11. Сборка для Pages — через BASE_PATH из имени репозитория
`vite base` берётся из env в CI; локально и в превью — `/`. Ресурсы относительные.

### D-12. Файл CI (GitHub Pages) хранится в `docs/ci/` — ограничение токена
Токен агента (GitHub App) не имеет права `workflows`, поэтому пуш любого файла в
`.github/` отклоняется сервером. Готовый пайплайн (тесты → сборка с BASE_PATH →
деплой на Pages) лежит в **`docs/ci/deploy.yml`** с инструкцией в шапке. Владельцу:

```bash
mkdir -p .github/workflows && cp docs/ci/deploy.yml .github/workflows/deploy.yml
git add .github/workflows/deploy.yml && git commit -m "ci: включить Pages-деплой"
```

(или выдать токену право workflows). До этого «живая» проверка — превью-сервер песочницы;
сборка и тесты прогоняются перед каждым коммитом.

### D-13. Баланс откалиброван автоматическим пробом (probe), не «на глаз»
Винрейт босса цикла 1 армией середины игры (рыцарь + 2 лучника, 2 редких предмета,
4 технологии, без построек): 9/10 побед за 1–5 попыток по 10 разным seed.
Промежуточные выводы: экипировка врагов сделана «bare» (без аффиксов и сетов,
качество 0.9), босс не получает дополнительного множителя сверх скейлинга слоя,
глубина слоя 5%/узел, цикл +28%. Догма: любая правка баланса проверяется пробом.

## Фаза 1

### D-14. Звук — синтез WebAudio, без аудио-файлов
Плейсхолдер-бипы генерируются осцилляторами/шумом (`src/utils/sound.ts`): удар — шумовой
щелчок, крит — двойной тон, смерть — нисходящий пилобразный, победа/поражение — арпеджио.
Ассеты не нужны, бандл не растёт, звук отключается кнопкой 🔊. AudioContext ленивый —
политика автоплея браузеров соблюдается (первый звук после клика игрока).

### D-15. Поле боя рисуется как 5 линий глубины, а не сетка 10×20
Из 10×20 клеток игроку важна только глубина (линия) — колонка влияет лишь на тай-брейки.
Каждая сторона — стопка из 5 «полос» (фронт подсвечен, тыл полупрозрачен), у врага порядок
инвертирован так, что фронты соприкасаются у разделителя. Читается геометрия дальности.

### D-16. Яд игнорирует щит
Урон яда проходит мимо щита: (а) тематически верно — это внутренний урон; (б) кадр
воспроизведения (`playback.ts`) восстанавливает HP из события, и если бы щит поглощал яд,
реплей разошёлся бы с симуляцией. Тест «финальный кадр ≡ final» фиксирует это свойство.

### D-17. Воспроизведение боя — чистая функция движка
`computeFrameState(result, upto)` в `engine/combat/playback.ts` — единственный источник
состояния экрана боя. UI не хранит собственный мутирующий слепок: любой кадр
восстанавливается заново, реплей/таймлайн/тесты используют одну и ту же функцию.
