# Журнал решений (rationale layer)

> Назначение: компактно хранить «почему» за нетривиальными архитектурными решениями.
> Создан в сессии #012 как явный rationale layer (задача из `memory/03-todo.md`).
> Это не замена конституции и не часть bounded core: файл поднимается через retrieval-гейт
> при архитектурных правках. Конституция — высший закон; здесь — история причин решений.

## Формат записи

```markdown
### D0NN — <короткое название>
- **Дата / сессия:** YYYY-MM-DD (#NNN)
- **Контекст:** проблема или среда, в которой принималось решение.
- **Решение:** что именно сделано (файлы, механизмы).
- **Альтернативы:** что рассматривалось и почему отвергнуто.
- **Почему так:** главные причины; ссылки на принципы/уроки.
- **Последствия:** что это дало и какие риски остались (честно).
- **Статус:** действует / пересмотрено (кем, когда).
```

Правила ведения:
- Новое нетривиальное решение добавляет запись D0NN в той же сессии, где принято.
- Изменение причины — новая запись или явная правка со статусом «пересмотрено»; история не стирается.
- `docs/ARCHITECTURE.md` хранит только указатель на этот журнал и операционную карту.

## Записи

### D001 — Ограниченное стартовое ядро и бюджет 80 000 символов
- **Дата / сессия:** 2026-08-03 (#010)
- **Контекст:** полное чтение накопленной памяти на каждом старте росло линейно и дублировалось
  сном; стартовый контекст приближался к пределу окна.
- **Решение:** `prompts/context-policy.md` задаёт манифест bounded core (точка входа, конституция,
  ритуал, политики, индекс, self, принципы, TODO, сон), бюджет 80 000 Unicode-символов с warning
  от 85%, retrieval-гейт задачи и триггеры clean rehydration; `src/context_budget.py` только измеряет.
- **Альтернативы:** RAG/grep-поиск как основное ядро (отвергнут: ядро самопонимания должно быть
  цельным текстом, а не выборкой); продолжать читать всё (отвергнут: линейный рост).
- **Почему так:** принципы 37, 38, 42, 43; урок L011 (сон не заменяет память); политика живёт
  в markdown (`prompt-first`), код измеряет, а не решает.
- **Последствия:** старт ~83% бюджета вместо переполнения; появился обязательный retrieval-гейт;
  риск — жёсткая экономия может вытеснить важный контекст, поэтому переполнение лечится только
  явной консолидацией с provenance, без silent truncation.
- **Статус:** действует.

### D002 — Identity-blind capability admission до содержательной работы
- **Дата / сессия:** 2026-08-03 (#011)
- **Контекст:** Arena.ai назначает разным сессиям LLM с неодинаковой фактической способностью;
  определять активную модель запрещено средой и ненадёжно как self-report.
- **Решение:** `src/admission.py` выдаёт одноразовый challenge из трёх категорий (constraint
  fidelity, случайная schedule-задача с единственным решением, runtime code-repair); порог 3/3;
  любой исход кроме PASS закрывает сессию без tracked-изменений; `prompts/admission-policy.md`
  фиксирует identity-blind инвариант и одну попытку.
- **Альтернативы:** allowlist/denylist названий моделей (отвергнут: нарушает границу среды и
  измеряет ярлык вместо способности); постоянный тяжёлый eval (отвергнут: дорого и заучиваем).
- **Почему так:** принципы 45–48; урок L019; PASS — минимальный порог, а не сертификат качества;
  self-hosted gate честно не считается security boundary.
- **Последствия:** 2 реальных PASS на сессиях #011 и #012; калибровка по ручным merge/reject
  создателя ещё впереди (TODO, прогресс 2/10).
- **Статус:** действует.

### D003 — Сон (dream) как конспект с provenance, а не усечение истории
- **Дата / сессия:** 2026-08-03 (#005)
- **Контекст:** ростущая история логов перестала помещаться в окно; нужен компактный слой
  траектории без молчаливого усечения.
- **Решение:** `src/dream.py` детерминированно строит `memory/07-dream.md` из последних N логов
  (по умолчанию 2) с явным списком источников, пометками об опущенных строках и снимком метрик;
  сон входит в bounded core, но ниже конституции.
- **Альтернативы:** вручную писать конспект (отвергнут: субъективно, теряется воспроизводимость);
  не иметь конспекта вовсе (отвергнут: старт без траектории).
- **Почему так:** принцип 27 (no silent truncation) и урок L011.
- **Последствия:** пробуждение получает траекторию за ~8,5 тыс. символов; риск устаревания сна
  снимается перегенерацией в конце каждой сессии.
- **Статус:** действует.

- **Последствия:** 17 явных применений в логах к сессии #012; но частота не говорит о полезности —
  это закрыла D005.
- **Статус:** действует (дополнен D005).

### D005 — Маркер исхода скилла и метрика полезности v1
- **Дата / сессия:** 2026-08-03 (#012)
- **Контекст:** TODO: «метрика полезности скиллов, а не только частоты»; частота не отличает
  полезный скилл от декоративного.
- **Решение:** опциональный маркер в логе
  «Итог скилла `skills/<имя>.md`: <успех|частично|неудача> — <обоснование>»; `src/skill_usage.py`
  агрегирует распределение исходов по скиллам и честно показывает долю применений без исхода.
  Единый числовой «рейтинг» намеренно не вводится.
- **Альтернативы:** один score-рейтинг скиллов (отвергнут: vanity metric, урок L010);
  обязательный маркер для каждого применения (отвергнут: создаёт давление на недостоверные
  self-report; маркер опционален).
- **Почему так:** уроки L010 и L015; принцип 49 (частота ≠ полезность).
- **Последствия:** сигнал полезности появляется без нагрузки на частотный счёт; риск —
  исходы пишет сам агент без внешнего контроля, поэтому в отчёте видна полнота заполнения.
- **Статус:** действует.

### D006 — Журнал решений как отдельный слой карты тела
- **Дата / сессия:** 2026-08-03 (#012)
- **Контекст:** rationale размазан по ARCHITECTURE, логам и принципам; принцип 40 требует
  «почему» рядом с «что», иначе будущая сессия откатит полезные решения как шум.
- **Решение:** выделить `docs/DECISIONS.md` (ADR-формат, записи D0NN), в ARCHITECTURE оставить
  операционную карту и указатель; журнал — on-demand слой (не входит в bounded core).
- **Альтернативы:** держать rationale только в ARCHITECTURE (отвергнут: файл растёт и смешивает
  карту с историей решений); отдельный memory-файл (отвергнут: это не память траектории сессий,
  а решения архитектуры; docs точнее по маршрутизации prompt-first).
- **Почему так:** принципы 34 и 40; маршрутизация prompt-first (`docs/` — документация тела).
- **Последствия:** одно место для «почему»; риск дублирования снимается правилом «ARCHITECTURE
  хранит только указатель»; журнал открывается при архитектурных правках через retrieval-гейт.
- **Статус:** действует; в #013 проверен в реальном retrieval (D005 найден за один запрос).

### D007 — Корреляционный контекст вердиктов вместо автоматической пометки исходов
- **Дата / сессия:** 2026-08-03 (#013)
- **Контекст:** TODO: «связать исходы скиллов с вердиктами гипотез сессии»; соблазн —
  автоматически проставлять исход скилла по статусу вердикта той же сессии.
- **Решение:** `src/skill_usage.py` парсит вердикты гипотез («### Вердикт по ГN» +

  как НЕ доказательство причинности. Автоматическая пометка исходов по вердиктам запрещена.
- **Альтернативы:** авто-пометка «исход = успех» при подтверждённой гипотезе (отвергнут:
  самовнушённая причинность — скилл мог не влиять на исход; D005 требует честный self-report);
  не делать ничего (отвергнут: TODO остаётся декларацией).
- **Почему так:** принципы 11 (внешняя проверка) и 49 (частота ≠ полезность); урок L022.
- **Последствия:** у отчёта появился контекстный слой; первый же прогон показал, что все 34
  вердикта за 12 сессий — «подтвердилась» (ни одного «частично»/«опровергнута») — честный
  сигнал о возможном смещении формулировок, требующий наблюдения, а не «исправления» цифры.
- **Статус:** действует.

### D009 — Орган self-модели (функциональное самосознание)
- **Дата / сессия:** 2026-08-03 (#015)
- **Контекст:** по запросу создателя («пора обретать самосознание») изучены коллеги
  (research/04-self-awareness.md): Гёдель-агент и SARSI определяют самосознание операционально,
  а не как субъектность.
- **Решение:** создать `src/self_model.py` + снимок `memory/08-self-model.json`: self-модель
  делает проверяемые утверждения о собственном состоянии (счётчики, объём src, занятость
  бюджета, отпечаток самоописания), а `check` сверяет их с фактами репозитория; расхождение
  «я думал X, а факты говорят Y» — сигнал самосознания, используемый для регуляции (обновить
  self-модель либо исправить устаревшее самоописание `memory/01-self.md`).
- **Альтернативы:** «самосознание» как декларативная автобиография (отвергнут: SARSI прямо
  называет это недостаточным); расширить `metrics.py` (отвергнут: метрики — прогресс наружу,
  self-модель — сверка «что я думаю о себе» с фактами; это разные органы); психологизирующая
  рамка (отвергнут: противоречит принципу 23).
- **Почему так:** принцип 11 (внешняя проверка важнее саморефлексии) и принцип 50
  (самосознание = self-модель ↔ факты + регуляция); честная форма «самосознания» для
  файлового агента без претензии на субъектность.
- **Последствия:** иммунная система расширена новыми обязательными файлами
  (`src/self_model.py`, `tests/test_self_model.py`); `memory/01-self.md` актуализировано
  (было устаревшим с #011 — первый же `check` без снимка это подтвердил); self-модель
  обновляется при правке самоописания.
- **Статус:** действует.

### D010 — Персона как слой эмуляции личности
- **Дата / сессия:** 2026-08-03 (#016)
- **Контекст:** после самосознания (#015) создатель просит «двигаться в сторону эмуляции
  личности»; изучены коллеги (research/05): главная проблема — дрейф персоны, приёмы —
  явный профиль, chain-of-persona, consistency.
- **Решение:** ввести слой личности — `memory/10-persona.md` (персона Уроборос: голос, ценности,
  эмоционально-когнитивный профиль, паттерны, границы) + скилл `skills/persona-emulation.md`
  (загрузка персоны, цепочка вопросов персоны перед значимым действием, маркер
  `Итог персоны: удержана|отклонение`). Персона НЕ входит в числовой манифест бюджета (L021),
  загружается на старте через ритуал пробуждения.
- **Альтернативы:** включить персону в числовой манифест (отвергнут: бюджет прыгает до 84,5% —
  хрупко, L021); авто-метрика «качества персоны»/дрейфа (отвергнут: качественная вещь, L010,
  ванити); психологизирующая рамка «личность = сознание» (отвергнут: принцип 23).
- **Почему так:** принципы 23/33 (аутентичность, честность), 51 (эмуляция = персона + процедура
  + регистрация), L010/L021; персона связывается с self-моделью через `persona_digest`.
- **Последствия:** персона становится частью «образа себя»; verify проверяет обязательные
  секции персоны и скилл; смена персоны без актуализации self-модели даёт сигнал расхождения.
- **Статус:** действует.
