# Единая шкала эпох и выбор наследия — результат

Дата: 2026-10-02 · Ветка: `arena/01a0fab4-agi` · Проверки: `npm test` 169/169, `npm run typecheck` чисто, `npm run build` чисто, `node tools/economy-sim.js` — отчёт собирается.

## 1. Что было: рассинхрон лестницы эпох

`const ERAS` в `campaign.js` — единственный источник истины о том, какие эпохи есть в игре:

```
0 Каменный век · 1 Античный мир · 2 Средневековье · 3 Ренессанс
4 Эпоха Пара и Стали 1800-1910 · 5 Новейшее время · 6 Будущее 2050-2150
```

Все таблицы, проиндексированные номером эпохи, были написаны под другую лестницу — Неолит → ранняя бронза → поздняя бронза → античность → средневековье → индустриал → будущее. Начиная с индекса 1 содержимое отставало от `ERAS` ровно на ступень:

| Где | Было | Симптом в игре |
| --- | --- | --- |
| `ERA_HISTORICAL` | `[1]` рассказывал про раннюю бронзу Месопотамии | на экране «Античный мир» игрок читал про Урук и неолит |
| `BRONZE_CARD_MIN_ERA` | `3` | бронзовый тег карт открывался только в «Ренессансе» |
| `battle.ts` (`enemyDeckForEra`) | `era >= 1` | враг получал бронзовую колоду в «Античности», игрок — нет |
| `campaign-map.js` | медь/олово `minEra 2`, железо `minEra 3` | бронза приходила в Средневековье, железо — в Ренессанс |
| дозоры на карте | эпохи вплоть до `3` | `BARBARIAN_DECK_SIZES[3]` не существует — бой без колоды племени |
| `CULTURE_UNITS_BY_ERA` в `legacy.html` | пулы только для эпох 0, 1, 2, 3 и 6 | в «Эпохе Пара и Стали» ковались казаки и янычары, в пуле Средневековья лежали ассирийцы |
| переход эпохи | случайная ассимиляция: кандидат эпохи попадал в линию, с шансом 30 % молча заменял культуру народа | игрок терял бонусы своего наследия без решения и без объяснения |

## 2. Что стало: одна лестница на всю игру

| Индекс | `ERAS` | Ключевой ресурс эпохи | Месторождения на карте | Эпохи карт | Ветвей науки (новых) | Культур |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | Каменный век | обсидиановая мастерская | обсидиан — 0 | `ancient` | 6 (+6) | 6 |
| 1 | Античный мир | медная плавильня + оловянный торговый стан (бронза) | медь — 1, олово — 1 | `ancient`, `bronze` | 11 (+5) | 13 |
| 2 | Средневековье | железоплавильня | железо — 2, поселение соседа — 2 | `ancient`, `bronze` | 12 (+1) | 10 |
| 3 | Ренессанс | нет гейта | — | `ancient`, `bronze` | 15 (+3) | 9 |
| 4 | Эпоха Пара и Стали 1800-1910 | нет гейта | — | `ancient`, `bronze` | 17 (+2) | 9 |
| 5 | Новейшее время | нет гейта | — | `ancient`, `bronze` | 19 (+2) | 8 |
| 6 | Будущее 2050-2150 | нет гейта | — | `ancient`, `bronze` | 21 (+2) | 8 |

Принятые решения (по ответам на вопросы):

- **Гейты — «ровная прогрессия»**: обсидиан в эпоху 0, бронза (медь + олово) в эпоху 1, железо в эпоху 2, потолок эпох дозоров `GUARD_ERA_CAP = 2` (= `BARBARIAN_ERA_CAP`).
- **Эпохи карт — «keep2»**: поле `era` у карты остаётся боевым тегом `ancient | bronze`; бронза открывается игроку с эпохи 1 (`BRONZE_CARD_MIN_ERA = 1`) — ровно как врагу в `battle.ts`. Реальная эпоха кампании передаётся в промпт кузнеца текстом: название эпохи, `ERA_HISTORICAL[era].desc`, `.cultures`, `.tech` и прямое указание, что образы и технологии обязаны ей соответствовать (мушкеты и печатный стан для Ренессанса, пар и сталь для 1800-1910, танки и авиация для Новейшего времени), хотя тег остаётся `ancient|bronze`.
- **Контент — «полный»**: написаны заново все семь строк `ERA_HISTORICAL`, 63 культуры, пулы кузнеца для эпох 4 и 5, из пула Средневековья убрана античность.
- **Сохранения — «без миграции»**: см. раздел 7.

## 3. Технологии эпохи не зависят от наследия

Все гейты читают только `player.era`:

- `ERA_KEY_RESOURCE = { 0: obsidian-workshop, 1: smelter + caravan, 2: ironworks }`, эпохи 3–6 без ключа;
- `hasEraKeyResource(state)` — эпоха + активные постройки; потребители: редкость ковки (`rareLocked`), цена заказа кузнеца и `constructBlueprint`;
- `scienceBranchesForEra(era)`, `allowedCardEras(era)`, `getAvailableMaterialQualities(state)`, `BRONZE_CARD_MIN_ERA`;
- культура даёт только бонусы народа (склад, производство, лимит колоды, HP, энергия) и «вкус» для кузнеца.

Тест прямо сравнивает ветки «сохранил прежнее» и «принял культуру эпохи»: наборы `scienceBranchesForEra`, `allowedCardEras`, `hasEraKeyResource` и причина отказа по медной жиле совпадают; различаются только бонусы народа.

## 4. Выбор наследия при переходе эпохи (новая механика)

Случайная ассимиляция удалена. Переход эпохи в `researchBlueprint` теперь:

1. повышает `player.era`, подтягивает племена (`bringBarbariansAlong`) и открывает уклад (`pendingDecreeChoice`) — как раньше;
2. закрывает неотвеченный выбор прошлой эпохи записью в летопись («выбор наследия так и не был сделан — народ сохранил …»);
3. открывает `player.pendingCultureChoice = { era, candidates, openedDay }` — до 3 (`CULTURE_CHOICE_SIZE`) культур этой эпохи, которых ещё нет в линии наследия; отбор детерминирован (seed по имени народа, клану и эпохе), поэтому перезагрузка сохранения показывает тот же список;
4. пишет в летопись эпоху, её описание и перечень технологий («Технологии эпохи: …»), а в `campaignNotice` — напоминание про выбор.

API модели (единый для обеих оболочек):

```js
getCultureChoice(state)      // { era, eraLabel, eraDescription, eraTechnologies, current, candidates, keep } | null
chooseCulture(state, id)     // id = 'keep' | cultureId → { state, error, culture, kept }
cultureCandidates(state, era)
normalizeCultureChoice       // часть normalizeState: чужая эпоха и битые данные отбрасываются
```

`chooseCulture` отказывает, если: выбор не открыт; культура не из числа предложенных; бонусы культуры урезали бы боевую колоду ниже `player.deckCardIds.length` (та же защита, что у `chooseDecree`) — наследие при этом не меняется, а выбор остаётся открытым, чтобы игрок сначала разобрал колоду. «Сохранить прежнее наследие» разрешено всегда.

## 6. Карта, бой и сим экономики

- `campaign-map.js`: константы `BRONZE_SITE_MIN_ERA = 1`, `IRON_SITE_MIN_ERA = 2`, `GUARD_ERA_CAP = 2` объявлены рядом и экспортируются в `api`, вместо разбросанных литералов. Проверено на 15 мирах: обсидиан — 0, медь и олово — 1, железо — 2, поселение соседа — 2; эпохи дозоров ⊆ {0, 1, 2} (распределение `{0: 87, 1: 197, 2: 6}`); для каждой клетки `guard.era >= tile.minEra`, то есть охрана никогда не сильнее эпохи, в которую земля открывается.
- `src/game/battle.ts`: порог бронзовой колоды врага не менялся (`era >= 1`) — теперь он совпадает с игроком; рядом добавлен комментарий-ссылка на `BRONZE_CARD_MIN_ERA`, чтобы порог не разъехался снова (файл импортирует только `./cards`, общей константы из `campaign.js` здесь нет намеренно).
- `tools/economy-sim.js`: `unlockMaterialSites` для мастерской работы захватывает теперь медную жилу, оловянный путь **и** железную жилу — по новой лестнице редкая ковка на эпохе 2 упирается в железо. Frontier-сценарий: `forgedCardRarity: 'rare'`, день 30, доступные качества `['standard', 'refined', 'masterwork']`.

## 7. Сознательный компромисс: старые миры не мигрируют

По решению «сохранения = без миграции» версии не менялись: `campaign-map.js → WORLD_VERSION` остался `2`, версия кампании — `4`, ключ — `iforge_campaign_v4`.

Следствие, о котором нужно помнить: **миры, сгенерированные до этой правки, хранят в клетках прежние `minEra`** (медь и олово — 2, железо — 3) и прежние эпохи дозоров (до 3). Модель теперь гейтит по `player.era`, поэтому в старом мире на эпохе 1 «Античный мир» редкая ковка упрётся в медь и олово, которые карта по-прежнему откроет только с эпохи 2. Лечится это стартом нового мира — старый не пересоздаётся и не «чинится».

Если мягкая миграция понадобится, её место — загрузка мира в `campaign-map.js`: переписать `tile.minEra` по `siteType` (copper/tin → 1, iron → 2, settlement → 2, obsidian/salt → 0) и обрезать `guard.era = Math.min(guard.era, GUARD_ERA_CAP)`. Сейчас это не реализовано намеренно.

## 10. Как проверить

```bash

npm run build            # vite build + singlefile
node tools/economy-sim.js
```

Вручную: `npm run dev` → «Развитие» → вкладка «Наследие». Две изученные науки переводят народ в эпоху «Античный мир»: появляется выбор из трёх культур эпохи (например «Аккад Саргона | Хетты | Ассирия») и кнопка «Оставить прошлое наследие». В обоих случаях ветвь «Бронзовые сплавы» и бронзовый тег карт уже доступны — отличается только бонусы народа и строка «Линия культур» в хронике.
