# Механизм Цивилизации (Cog Empires) — Game Design Document

> Элевейтор-питч: стратегия, где игрок развивает упрощённую цивилизацию через дерево
> технологий с синергиями иконок, чтобы добывать редкие **шестерёнки** — модульные
> компоненты для глубокой кастомизации **трёх своих отрядов**. Бой — пошаговый
> автотактический, с сетами экипировки и системой морали/отступления.

---

## 1. Ключевые дизайн-решения (не пересматриваются без явного запроса)

1. **Микро важнее макро.** Бой и юниты — главный контент; цивилизационный слой — экономика, кормящая бой.
2. **Три отряда, а не армия.** Каждый юнит на счету, каждый предмет заметен.
3. **Геометрия боя:** поле 10×20; 5 линий на сторону по 2 ряда; позиционирование только стартовое — дальше решает таргетинг по тегам/дальности. (Полная сетка с движком была сознательно отклонена.)
4. **Экипировка = шестерёнки:** рандомный дроп с редкостью Common → Legendary, слияние 3 → 1.
5. **Технологии дают иконки** (Craft/Lore/Culture/War/Mining/Agri); набор иконок активирует **догмы** — пассивные бонусы (прямая параллель с Innovation).
6. **Бой:** симуляция по раундам, детерминированный урон + управляемый рандом (попадание/крит/уклонение), фаза «Внезапной атаки» до основных раундов.
7. **Прогрессия:** узловая карта кампании; после Босса — новый Цикл (NG+) с ростом сложности.
8. **Мультиплеер отложен.** Сначала полируем PvE-петлю.

## 2. Петля игры (core loop)

```
Кампания (узел) → Бой → Добыча/Доход → Город (постройки) / Технологии (наука)
      ↑                                          ↓
      └──────────── Мастерская (слияние) ← Коллекция шестерёнок
```

- Каждый узел = 1 день дохода (привал = 2). Доход тратится на постройки, наём, слияние.
- Наука копится всегда; технологии дают иконки + эффекты + разблокировки (рекруты, здания).
- Догмы = «комбо» из иконок: например, ⚔×3 → «Кодекс воина» (+10% атаки всем).

## 3. Бой

### 3.1 Поле и линии
- 10 колонок × 20 рядов. Сторона игрока — ряды 0–9, врага — 10–19.
- Линия = 2 ряда. Линия 0 — фронт, линия 4 — тыл.
- Дистанция между юнитами считается от передней линии стороны: `своя_глубина + чужая_глубина + 1`.
- Юнит бьёт цели в пределах своей **дальности** (range 1 — только фронт-в-фронт, 3–4 — через линии).

### 3.2 Порядок и фазы
1. **Фаза внезапной атаки:** юниты с `firstStrike` или скоростью ≥ 1.25× максимальной скорости врага бьют до начала боя (урон ×1.25).
2. **Раунды (до 30):** юниты ходят по убыванию скорости (тай-брейк — стабильный случайный джиттер по seed). В начале раунда: регенерация, урон яда, проверки морали.
3. **Конец:** сторона без активных (живых и не бежавших) юнитов проигрывает; лимит раундов — ничья.

### 3.3 Формулы
- Шанс попадания: `clamp(acc − eva, 5..100)`. Контратаки всегда попадают.
- Крит: бросок `crit%`, урон × `critDmg%` (база 150%).
- Урон: `atk × variance(0.9–1.1) × (крит?) × (казнь?)`, затем `× 100 / (100 + def × (1 − armorPen))`, минимум 1.
- Яд: стаки × 3 урона в начале раунда, −1 стак после срабатывания (макс. 10).
- Щит: поглощает урон до исчерпания, не лечится.
- Вампиризм: % нанесённого урона возвращается как лечение.

### 3.4 Мораль и бегство
Мораль меняется событиями: смерть союзника −15, убийство врага +10, потери 50% HP −10, 25% HP −15, полученный крит −5, бегство союзника −7. Ниже порога 25 юнит каждый раунд проверяет `(25 − мораль) × 4%` шанс **бегства** (покидает бой). Тег `fearless` (скелеты, боссы, Эгида) игнорирует мораль.

### 3.5 Таргетинг
Правило юнита задаётся рекрутом и может переопределяться оружием: `nearest` (ближайшая линия → слабейший % HP), `weakest` (наименьший HP), `strongest` (наибольшая атака), `ranged` (сначала стрелки), `random`. Способность «Охотник» добавляет приоритет по тегу. Тай-брейки детерминированы: дистанция → |колонка| → id.

### 3.6 Способности
`firstStrike`, `poisonOnHit`, `cleave` (вторая цель в линии), `doubleStrike`, `retaliate` (контратака на ближний удар), `regen`, `execute` (бонус по раненым), `rally` (мораль за убийство), `shield`, `targetPref`. Одинаковые способности сливаются (стаки складываются, шансы/множители берутся по правилам в `computeUnit.mergeAbilities`).

## 4. Экипировка

- **4 слота:** оружие, броня, амулет, ядро. Оружие задаёт стихию юнита и может переопределить таргетинг.
- **Редкость** определения фиксирует пул: у каждой редкости свой список предметов (генератор выбирает редкость по весам узла, затем предмет).
- **Экземпляр** = определение + качество (0.85–1.15, множитель статов) + аффиксы (0–2 случайных стата по редкости) + цикл добычи.
- **Сеты** (Дракон/Волк/Бастион/Змей/Мудрец): бонусы за 2/3/4 предмета одного сета на юните. Полный сет красит стихию.
- **Слияние 3 → 1** в Мастерской: три предмета одной редкости → один выше; ≥2 входов одного сета → результат из сета; 3 входа одного слота → тот же слот. Легендарные не сливаются. Стоимость в руде, скидки от Кузницы/догм.
- **Разбор** в руду. Надетые предметы не разбираются.

## 5. Экономика и технологии

- Ресурсы: **еда** (наём), **руда** (слияние/разбор), **наука** (технологии), **золото** (постройки/наём).
- Доход в день: база + постройки × уровень, затем × (1 + бонусы%).
- Постройки: Ферма, Шахта, Библиотека, Рынок, Казармы (+HP%), Кузница (−цена слияния), Святилище (+мораль).
- Технологии: 3 эры, граф требований; каждая даёт иконки, эффект и/или разблокировку.
- **Догмы** по иконкам: пороги 3 и 5 одного типа, плюс комбо 2+2 (Оружейники, Трансмутация, Героический эпос, Инфраструктура).

## 6. Кампания и циклы

- Карта 8 слоёв: старт → бои → (элита | сокровище) → привал → (элита | бой) → привал → **Босс**.
- Из узла 1–2 выхода — лёгкий ветвящийся выбор пути (Slay the Spire-стиль).
- Стычка (фарм) доступна всегда вне карты.
- Победа над Боссом = **Цикл +1**: статы врагов ×(1 + 0.3×(цикл−1) + 0.06×слой), босс ×1.2; веса добычи сдвигаются к редкому.

## 7. Архитектура (для инженеров)

- `src/engine/**` — чистые функции, никакого I/O; вся случайность через `Rng(seed)`.
- `src/data/**` — только контент с типами; баланс правится в одном месте.
- `src/store/**` — Zustand-стор: единственное место, знающее про localStorage.
- `src/components/**` — только рендер; состояние и логика — в сторе/движке.
- Тесты фиксируют детерминизм: `simulateFight(одинаковый seed) === идентичный результат`.
