# Спецификация активного контекста

> Статус: операционная спецификация. Она **не заменяет** конституцию и не может отменять
> обязательный ритуал пробуждения из `memory/00-constitution.md` и `prompts/awakening.md`.

## Зачем она нужна

Полный архив репозитория ценен, но не весь он нужен для каждого решения. Смешение конституции,
текущей задачи, старых логов и длинных выводов в одном рабочем окне повышает риск context rot.
Эта спецификация задаёт границу: что держать в активном рассуждении, что открывать по ссылке и
когда честно завершать сессию ради clean rehydration.

## Слои информации

| Слой | Состав | Режим | Назначение |
|---|---|---|---|
| Защищённое ядро | Конституция, индекс, self, принципы, TODO, глоссарий, уроки, dead ends, сон и предыдущий лог | Обязательное чтение при пробуждении, в порядке ритуала | Идентичность, ограничения, ближайшая траектория и опыт |
| Рабочая дельта | Текущий лог, гипотезы, файлы задачи, краткие результаты проверок | Держать активным только пока решается задача | Принять и проверить следующее решение |
| Архив по запросу | Старые логи, исследования, полный git-лог, большие отчёты команд | Открывать по конкретной ссылке/вопросу; извлекать фрагментом | Проверить происхождение и детали без перегрузки |
| Шум | Повторённый stdout, черновые рассуждения без вывода, нерелевантные фрагменты | Не переносить в новые записи; сохранять только если нужен воспроизводимый след | Не загрязнять последующее мышление |

Защищённое ядро не означает, что его нужно бесконечно цитировать или держать целиком в каждой
мысли. После обязательного чтения в активной работе остаётся только дельта, которая нужна для
текущей задачи; первоисточник остаётся доступен в файле.

## Сборка контекста для задачи

1. Выполнить обязательное пробуждение без сокращений.
2. В логе сформулировать одну–пять задач и гипотезы.
3. Для каждой задачи назвать минимальные файлы рабочей дельты и открыть только их.
4. Если требуется факт из архива, сначала записать вопрос, затем открыть конкретный источник,
   а в активный лог вынести вывод и ссылку, а не большой фрагмент.
5. Выводы объёмных команд сохранять во внешнем файле только при необходимости; читать их через
   `grep`, `tail`, diff или адресный фрагмент.
6. По окончании задачи обновить устойчивый слой (лог, урок, TODO, исследование или dead ends),
   чтобы следующий старт не зависел от исчезающего диалога.

## Триггеры clean rehydration

Нужно остановиться, применить `skills/context-hygiene.md` и предпочесть корректное закрытие
сессии новому старту, если наблюдается хотя бы один сильный либо два слабых сигнала.

**Сильные сигналы:**
- невозможно кратко назвать текущую задачу, гипотезу и следующий шаг;
- в записях появляются несвязные фрагменты, случайные числа или противоречащие друг другу выводы;
- повторяется действие без новой гипотезы или нового внешнего сигнала;
- для продолжения требуется держать в голове большой сырой transcript вместо устойчивых файлов.

**Слабые сигналы:**
- более двух больших выводов команд подряд попали в рабочее обсуждение;
- архивный материал читается целиком, хотя нужен один факт;
- задача распалась на несколько несвязанных подзадач;
- после одной попытки проверки неясно, что именно изменится во второй.

Это не автоматический диагноз и не разрешение бросать работу. Перед rehydration нужно сохранить
рабочую дельту: обновить лог, зафиксировать состояние гипотез, отметить следующий шаг и выполнить
ритуал закрытия. Новый старт снова читает защищённое ядро и последний лог, а не опирается на память
старого окна.

## Проверяемые инварианты

- Сокращённая спецификация никогда не заменяет обязательное чтение ядра.
- Каждый содержательный архивный вывод имеет источник или пометку о своей неопределённости.
- В логе остаётся краткий результат действия, а не неконтролируемая копия stdout.
- Решение о clean rehydration содержит причину и сохранённый ближайший следующий шаг.
