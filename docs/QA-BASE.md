# Направление 05: экспедиционная база

10 октября 2026. Реализована личная база «Странник» для существующей
трёхпредметной экспедиции. Разделение работы — по подсистемам, проверки
проводились одним агентом, без утверждений о независимой команде.

## 1. Состояние, груз и исследования

Отдельный `base-state.js` содержит доставку, исследование, данные,
оборудование и финальную передачу. Баланс данных не хранится отдельным
изменяемым числом: он выводится из количества исследований и купленных
улучшений. Повторная доставка, анализ или покупка не выдают награду.
Исследование требует доставленного, ранее расшифрованного образца.

Валидация удаляет неподтверждённые зависимости и недоступные покупки.
Старые сохранения получают пустую базу; расшифрованные реликвии остаются
при игроке, готовые к доставке. Заново собирать их не требуется.
Сброс очищает и полевой, и базовый прогресс.

**Отдельные тесты:** миграция, невозможные зависимости, двойные действия,
недостаток средств, неизвестные улучшения, сохранение и сброс,
условия финальной передачи.

## 2. Оборудование действительно влияет на инструменты

Спектральный процессор сокращает игровую длительность сканирования с 4,2
до 2,4 секунды. Скорость волны синхронизирована с этой длительностью,
чтобы радиус покрытия не уменьшался. Насадка умножает усилие очистки на
1,5 и для raycast-кисти, и для кнопки/клавиатуры.

В браузере проверено: до установки один программный click кнопки очистки
даёт 12%, после установки — 18%. Параметры оборудования считываются из
валидированного состояния, а не из надписей UI. Исследования и покупки
не привязаны к несуществующим деньгам или внешним сервисам.

## 3. Мир и кабина

Добавлены внешний корпус с опорами, шлюзом и антенной, отдельная 3D-кабина,
лабораторный стол с инструментом, коммуникационный терминал, шкафы,
три физических постамента и окно с упрощённым ландшафтом.
Доставленные предметы — те же модели, что в поле и осмотре; витрины
синхронизируются со статусом доставки, включая сброс.

Кабина создаётся один раз и остаётся в кэше. Используется один renderer;
RenderPipeline переключает активную сцену. При выходе восстанавливаются
позиция, ориентация и FOV полевой камеры. Границы передвижения ограничивают
проходимый коридор между столами и перед витринами.

**Первый визуальный разбор:** корпус монитора перекрывал повёрнутую
плоскость экрана. Исправлено общей системой координат корпуса и экрана
с сохранением трансформации при объединении статической геометрии.
Многогранные силуэты за окном заменены эродированными сглаженными скалами;
добавлены вентиляционные решётки, фасады шкафов и разметка прохода.

## 4. HUD, станции и карта

В поле добавлены кнопка базы, счётчик груза, метка корпуса и переход с карты.
На борту — отдельный HUD, манифест груза и четыре доступных раздела:
лаборатория, коллекция, терминал, карта. Кнопки станций — альтернативный
способ доступа, не требующий точного управления камерой.

При первом входе был замечен краткий остаток полевого dock под новым HUD.
Скрытие заменено с `visibility` на `display:none`: полевая панель не должна
ни отображаться, ни принимать фокус на борту. Символы коллекции используют
те же векторные знаки, что и дешифровка, без редких Unicode-глифов.

Переход на базу прекращает незавершённый скан и автопереход. Исследование
находки с карты сначала возвращает в поле. Esc закрывает текущее окно;
без окна на базе — возвращает в поле. Все исследования и покупки доступны
через обычные кнопки и клавиатуру, не только через 3D.

## 5. Проверки и ограничения

- `npm test` — 23 теста состояния, геометрии и навигации.
- `npm run test:base` — старое сохранение, движение по кабине, доставка,
  анализ, запрет покупки без данных, оба улучшения, две реальные вылазки,
  передача архива, reload, мобильная компоновка, осмотр и reset.
- `npm run test:base:visual` — высокое качество и фоторежим кабины,
  переиспользование сцены, три выставленных модели, E и границы прохода,
  390×844 / 390×667 / 844×390, отмена скана при переходе на базу.
- `npm run test:e2e` — прежняя экспедиция без посещения базы.
- `npm run test:interaction` — существующие мобильные взаимодействия.
- `npm run build`, `npm run format:check`, `git diff --check`.

Первый полный прогон base и прежнего e2e прошёл. Последующий старый
visual-check остановился по тайм-ауту 60 с на мобильном screenshot в
SwiftShader; это не засчитано как успешный прогон всех визуальных проверок.
Снимки базы проверяются отдельным сценарием, ошибки JS/WebGL собираются.

## Границы поставки

Это одна посещаемая кабина и завершённый цикл с тремя существующими
реликвиями и двумя улучшениями. Не добавлены строительство/перестановка
мебели, новые планеты, свободный полёт или полноценная navmesh-система.
Переход B — явно обозначенное быстрое перемещение, не симуляция полёта.
Анализ — действие с отчётом и наградой, без отдельной временной мини-игры.
Вид за окном — часть декорации кабины, не второй live-render полевого мира.
Одна оставшаяся единица данных после трёх исследований и двух покупок
сохраняется; она не требует траты для окончания экспедиции.

Качественные оценки AAA/9 из 10, реальный FPS и аппаратная совместимость
не выводятся автоматически из прохождения браузерных тестов.

### Результат повторной приёмки

После исправлений пройдены `test:base:visual`, `test:base` и
`test:interaction`; исключений JS и ошибок WebGL не обнаружено. Все
23 unit-теста, production-сборка, форматирование и проверка whitespace
прошли. Полная старая экспедиция `test:e2e` прошла в первом прогоне.

Снимки высокого качества, чистого вида кабины и трёх адаптивных размеров
сохранены в игнорируемой `.playwright/base-final-*.png`; desktop high и
компактный портрет просмотрены вручную. Высококачественный кадр кабины с
тремя предметами: 44 draw calls, 23 764 треугольника. Счётчики 71 геометрия
и 27 текстур включают также сохранённые ресурсы полевого мира и
постобработки, это не эксклюзивная стоимость кабины. Повторные переходы
не увеличивают число геометрий.
