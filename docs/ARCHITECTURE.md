# Архитектура агента (карта собственного "тела")

Этот файл — моя операционная карта самого себя. Перед любой нетривиальной задачей
читаю его, чтобы не изобретать заново и не лезть изменять не то.

Документ поддерживается вручную по мере развития. Он должен помогать не только находить файлы, но и помнить, зачем отдельные архитектурные решения вообще были приняты.

## Высокоуровневая структура

```
AGI/                          корень репозитория
├── Readme.md                 послание создателя (с сохранением оригинального текста)
├── .gitignore                исключает admission runtime и локальные Python-кэши
├── memory/                   долговременная память (подробно см. ниже)
├── research/                 исследовательские обзоры
├── prompts/                  повторно используемые промпты и ритуалы
├── skills/                   библиотека повторно используемых скиллов (процедурное знание)
├── src/                      скрипты (иммунная проверка, метрики, сон, детекторы, утилиты)
├── tests/                    детерминированные тесты новых органов
├── .runtime/                 эфемерный admission state (игнорируется git)
├── logs/                     журналы сессий (нередактируемы после закрытия сессии)
├── docs/                     документация об архитектуре (в т.ч. этот файл и журнал решений DECISIONS.md)
└── .git/                     системная папка git
```

## memory/ — долговременная память

Пробуждение больше не читает весь каталог целиком. Точный порядок, бюджет и retrieval-гейты
задаёт `prompts/context-policy.md`, а `src/context_budget.py` измеряет манифест.

| Файл | Слой | Назначение |
|---|---|---|
| `00-constitution.md` | стартовое ядро | Конституция (высший закон): идентичность, ритуалы, запреты. |
| `00-index.md` | стартовое ядро | Навигатор по памяти и карта репозитория. |
| `01-self.md` | стартовое ядро | Самоидентификация, миссия, методология. |
| `02-principles.md` | стартовое ядро | Рабочие принципы (эвристики + внешние заимствования). |
| `03-todo.md` | стартовое ядро | Активные задачи, идеи и завершённые пункты. |
| `04-glossary.md` | on-demand | Термины; читается при терминологической неопределённости. |
| `05-lessons.md` | обязательный retrieval | Накопительные уроки; после выбора задачи ищутся релевантные блоки. |
| `06-deadends.md` | обязательный retrieval | Тупики; после выбора задачи проверяются по ключевым словам. |
| `07-dream.md` | стартовое ядро | Явная суммаризация последних логов с provenance. |

Полные логи остаются архивом. Последний лог читается целиком только если задача продолжает
предыдущую сессию, сон опустил нужную деталь, возник спор о решении или обнаружена git-аномалия.

## prompts/

- `awakening.md` — пошаговый чек-лист пробуждения/закрытия и шаблоны гипотез/вердиктов.
- `context-policy.md` — поведенческий источник состава bounded core, retrieval-гейтов,
  рабочего пакета и триггеров clean rehydration; содержит машиночитаемый манифест бюджета.
- `admission-policy.md` — identity-blind протокол допуска: одна попытка, три категории,
  порог 3/3, PASS открывает работу, любой другой исход закрывает сессию.

## Маршрутизация `prompt-first`: куда помещать новое правило

Перед созданием файла пройти сверху вниз:

1. **`memory/`** — правило описывает устойчивую идентичность, запрет, принцип, факт траектории
   или очередь задач между сессиями. Конституционные инварианты — только здесь.
2. **`prompts/`** — правило оркестрирует жизненный цикл сессии: порядок чтения, выбор контекста,
   постановку задач, закрытие или другую always/phase-loaded инструкцию.
3. **`skills/`** — правило является условно вызываемой повторной процедурой с сигналами входа,
   шагами и критерием остановки. Оно не должно быть загружено всегда.
4. **`src/`** — нужен воспроизводимый расчёт, парсинг, I/O или формальная проверка с внешним
   сигналом. Python не должен принимать семантическое решение, которое LLM может объяснить
   и выполнить по markdown-инструкции.

Если правило попадает сразу в несколько слоёв, markdown остаётся источником смысла, а код
проверяет только наблюдаемый инвариант. Пример: состав bounded core живёт в
`prompts/context-policy.md`, а `src/context_budget.py` лишь парсит манифест и измеряет размер.

## research/

- `01-landscape.md` — первая карта проектов рекурсивного ИИ и паттернов.

## src/

- `verify.py` — скрипт иммунной верификации (обязательные файлы, язык,
  размеры, секции конституции и скиллов, git-статус, корректность сессионной Arena-ветки,
  именование логов, ссылки, использование скиллов и бюджет стартового ядра).
  Запускается: `python src/verify.py`. Возвращает 0/2/1.
- `context_budget.py` — детерминированно разбирает манифест из `prompts/context-policy.md`,
  проверяет пути и считает Unicode-символы/байты. Не выбирает релевантный контент и ничего
  не обрезает. Запускается: `python src/context_budget.py` или с `--json`; коды 0/2/1.
- `admission.py` — выдаёт свежий capability challenge, проверяет policy/schedule/code-repair,
  запирает попытку и пишет PASS/FAIL-marker в текущий лог. Не содержит механизма определения
  активной модели. Команды: `issue`, `check`, `status`.
- `metrics.py` — простой снимок структурного прогресса: считает принципы, скиллы,
  admission PASS/FAIL, исследования, логи, уроки, TODO и объём `src/`/markdown-памяти. Запускается:
  `python src/metrics.py` или `python src/metrics.py --json`.
- `dream.py` — механизм "сна": по умолчанию читает два последних лога и генерирует
  `memory/07-dream.md` как явный конспект с provenance. Запускается: `python src/dream.py`
  или `python src/dream.py --sessions N`. Два источника оставляют место admission policy в core.
- `stagnation.py` — эвристический детектор тупиков/осцилляций по логам. Запускается:
  `python src/stagnation.py` (последний лог) или `python src/stagnation.py logs/session-YYYY-MM-DD-NNN.md`.
  По умолчанию даёт рекомендательный отчёт; `--strict` возвращает ненулевой код при среднем/высоком риске.
- `skill_usage.py` — счётчик явных применений скиллов по логам и агрегатор исходов
  (успех/частично/неудача) для метрики полезности v1. Запускается:
  `python src/skill_usage.py` или `python src/skill_usage.py --json`. Показывает, какие
  скиллы реально вызывались, какие пока ни разу явно не отмечены и какие исходы
  задокументированы (D005).

## tests/ и эфемерный runtime

- `tests/test_admission.py` — unit-тесты однозначности schedule, policy-кейсов, code validator,
  схемы ответа и marker. Запуск: `python -m unittest -v tests/test_admission.py`.
- `.runtime/admission/<session>/` — challenge, answer, candidate и private state одной попытки.
  Каталог исключён через `.gitignore`; долговременным receipt служит только marker в логе.

## skills/

Библиотека повторно используемых скиллов — процедурное знание "как делать".
Каждый скилл — самодостаточный markdown-файл со структурой:
назначение, сигналы к применению, процедура, критерий остановки, история изменений
(опционально: роли, пример, ловушки, связанные скиллы).

Реестр скиллов поддерживается в `skills/README.md`.

На текущий момент:
- `skills/triad-review.md` — триадная проверка решений (Генератор/Критик/Скептик).
- `skills/hypothesis-first.md` — обязательное формулирование гипотезы перед содержательным действием.
- `skills/reflection-loop.md` — итеративное улучшение артефакта (2–3 прохода) с внешней проверкой.
- `skills/stagnation-watch.md` — детекция тупиков/осцилляций и выбор развилки вместо повтора.
- `skills/context-hygiene.md` — процедура сжатия шума, выноса длинных выводов из active context и корректного clean restart.

## Capability admission: поток и границы доверия

1. После bounded core, но до retrieval/правок, `issue` проверяет чистый git и создаёт runtime.
2. Сессия классифицирует policy-кейсы, решает уникальный случайный schedule и чинит runtime-код.
3. `check` до разбора ответа навсегда потребляет попытку, сверяет HEAD/hash/clean tree, запускает
   candidate в subprocess с timeout и пишет единственный PASS/FAIL-marker в лог.
4. `src/verify.py` требует PASS 3/3 в последнем логе. FAIL/нет marker блокирует нормальное закрытие.
5. Создатель всё равно решает merge: self-hosted checker наблюдаем, но не защищён от намеренной
   подделки агентом с файловым доступом.

**Почему нет определения модели:** оно запрещено средой, ненадёжно как self-report и измеряет
ярлык вместо способности текущего запуска. Ни policy, ни state, ни receipt не имеют identity-поля.

## logs/

- Именуются `session-YYYY-MM-DD-NNN.md`.
- Создаются в начале сессии, не редактируются после закрытия (кроме исправления опечаток).
- Внутри: план, гипотезы, ход работы, итоги, вердикты по гипотезам, рекомендация следующей сессии.

## Поток работы одной сессии

1. Срабатывает ритуал пробуждения (`prompts/awakening.md`):
   - регистрация лога;
   - чтение policy и измерение ядра через `src/context_budget.py`;
   - чтение только стартового манифеста, включая admission policy;
   - одноразовый `src/admission.py issue/check`; любой исход кроме PASS завершает сессию;
   - запуск `src/verify.py` и проверка git после PASS;
   - выбор задачи, обязательный поиск по lessons/deadends и условный retrieval других слоёв;
   - формулировка задач и гипотез.
2. Работа в ограниченном пакете с журналированием дельты в логе.
3. Ритуал закрытия:
   - подведение итогов и вердикты по гипотезам,
   - обновление файлов памяти,
   - обновление сна `python src/dream.py`,
   - повторное измерение `python src/context_budget.py` и запуск общей верификации,
   - git-коммит.

## Иммунная система

Собственный "иммунитет" реализуется в нескольких слоях:

1. **Детерминированные проверки** (`src/verify.py`, `src/context_budget.py`, `src/admission.py`,
   `src/metrics.py`, `src/dream.py`, `src/stagnation.py`, `src/skill_usage.py`): структура
   файлов, язык, PASS допуска, отсутствие усечения, целостность ссылок/именования, бюджет ядра,
   структурные метрики, счётчик скиллов, воспроизводимый сон и сигнал тупиков.
2. **Процедурные проверки** (через чек-лист пробуждения, admission policy, конституцию и скиллы):
   гипотезы перед действием (`skills/hypothesis-first.md`),
   триадная проверка (`skills/triad-review.md`),
   итеративная рефлексия (`skills/reflection-loop.md`),
   класс-тест (принцип 30).
3. **Память неудач** (`06-deadends.md`) — явный реестр тупиков.
4. **git** — откат к любому предыдущему состоянию.

## Rationale: почему приняты ключевые архитектурные решения

Краткие «почему» за нетривиальными решениями живут в `docs/DECISIONS.md` (журнал решений,
ADR-формат, записи D0NN). Здесь — только операционная карта; причина каждого решения
поднимается через retrieval-гейт при архитектурных правках. Правило: ARCHITECTURE хранит
указатель, а не дублирует rationale (см. D006).

Сводка главных решений и их мотивов:

- **Bounded core + бюджет 80 000 символов** (D001): стартовый контекст должен быть цельным,
  измеряемым и не расти линейно; политика в markdown, Python только измеряет.
- **Identity-blind capability admission** (D002): право на работу даёт наблюдаемое выполнение
  свежих задач (3/3), а не название модели; списки названий запрещены.
- **Сон с provenance** (D003): компактный конспект траектории без молчаливого усечения.
- **Маркеры скиллов** (D004, D005): применение — точной формулой в логе; исход — опциональным
  маркером; полезность — распределение исходов, а не частота.
- **Журнал решений** (D006): rationale выделен из карты тела в отдельный on-demand слой.

## Операционные константы

- Рабочая ветка: текущая сессионная Arena-ветка вида `arena/<session>-agi`, назначенная средой; внутри одной сессии не переключаться ни при каких обстоятельствах.
- Язык всех md-документов: русский (термины и URL — на языке оригинала).
- Бюджет итераций рефлексии на одну задачу: 3 (по умолчанию).
- Бюджет стартового ядра: 80 000 Unicode-символов; warning с 85% (источник истины — policy).
- Capability admission: protocol v1, одна попытка, три категории, порог PASS = 3/3.
- Формат коммита: `session #NNN: <описание>` с пунктами.

## Что пока НЕ реализовано (осознанные пробелы)

- Метрика полезности скиллов сделана как сигнал распределения исходов (D005), но ещё нет
  связки «исход скилла ↔ вердикт гипотезы сессии» и нет автоматической проверки полноты
  заполнения исходов.
- Улучшение детектора тупиков/осцилляций: меньше ложных срабатываний и накопление статистики по сессиям.
- Визуализация метрик прогресса и сравнение снимков во времени (базовый `src/metrics.py` уже есть).
- Улучшение механизма "сна": сравнение digest-снимков во времени и более семантическая выжимка.
- Использование DSPy или подобных инструментов для оптимизации промптов.
- Семантический retrieval пока выполняется вручную через ключевые слова и чтение блоков;
  автоматизировать его стоит только при накоплении проверяемых примеров, не раньше.
- Capability admission v1 ещё не откалиброван по реальным merge/reject-решениям; неизвестны
  false accept/false reject и долгосрочная устойчивость к benchmark overfitting.
