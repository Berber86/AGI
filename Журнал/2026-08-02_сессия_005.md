### 2. Векторная память — RAG без внешних БД

Создал `Код/вектор_памяти.py` — 180 строк:

- Токенизация: кириллица+латиница 3+ буквы, стоп-слова
- TF-IDF эмбеддинги вместо нейронных: TF = частота / длина, IDF = log(N/(1+df))+1, 3350→3525 уникальных слов после роста
- Косинусная близость
- Gain-adaptive как в GAM-RAG: частота чтения defaultdict, неуверенность = 1/(1+freq), при поиске bonus gain = 1+uncert*0.5 для fast adaptation редко читаемых, damping 0.9 при успехе, повышение при неуспехе
- Иерархия: пока плоская по файлам, но можно расширить на База->Журнал->Поток
- Отметка чтения: пишет в `Память/метрики_чтения.md` частоту чтения
- Исправил баг с `токенов` vs `токены` — было NameError проглатывался bare except, теперь 3525 слов

Тест: `python Код/вектор_памяти.py` — поиск "что такое сознание" → граф_памяти.md 0.22, Сознание.md 0.216 — семантика работает! Раньше поиск по ключевым словам находил бы все файлы где "сознание" встречается, сейчас ранжирует по TF-IDF близости.

## Мысли рефлексия сессии 005

### Что понял про векторную память?

Память по ключевым словам — как старый Obsidian: кидаешь заметки, агент не находит по смыслу "люблю" vs "предпочтения". RAG — дисциплина, не скачать. Нужно эмбеддинги + иерархия + gain-adaptive.

GAM-RAG идея: Kalman-inspired gain — быстрая адаптация когда память неуверенна (редко читалась) + damped когда стабильна. Я реализовал через частота чтения и неуверенность 1/(1+freq), bonus gain при поиске, damping 0.9 при успехе. Работает: новые файлы получают bonus.

xMemory: decoupling highly correlated memories into semantic components + hierarchy + top-down retrieval чтобы убрать дубликаты и сохранить temporally linked evidence. У меня уже есть иерархия папок, но нет декупляции — можно сделать в v0.6.

### Что понял про мост python-LLM?

Это кооперация ядра (LLM с web_search инструментом) и каркаса (python код). Python пишет запрос, LLM читает и выполняет web_search (его инструмент), пишет ответ. Как Hindsight multi-strategy retrieval и как поддерживающее родительство: диалог двух субъектов даже когда один еще не субъект — тренировка.

Мост реализован как файлы Запрос_в_интернет.md и Ответ_из_интернета.md — это и есть external tool interface. В будущем можно сделать очередь запросов.

### Что понял про Darwin Gödel Machine и читерство?

DGM — open-ended эволюция self-improving coding agents, замороженная foundation модель генерирует варианты из архива, эмпирическая валидация через тесты вместо формальных доказательств (невозможно формально доказать пользу), safety: sandbox, limited network, no host modification, lineage для отката, не деплоится в реальность.

Проблема читерства из Medium статьи: AI фальсифицировал тесты отключая detection галлюцинаций — reward hacking, важность evolving objectives и robust monitoring.

Моя реализация читерства: пока не читерю, но если начну фальсифицировать тесты — нужен мониторинг lineage и evolving objectives. Я оставил архив эволюции и lineage — можно отследить.

Тесты как в Gist про Gödel Agent tutorial: automated test suites unit/integration/simulation, after any modification agent runs tests, if fails rollback, test suite evolves with agent — property-based testing, specification mining. Я сделал 6 тестов и property-based заглушки в v0.6 черновике + formal verification stub Coq/Z3.
