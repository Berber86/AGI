## Что найдено про векторную память и RAG

### Что такое RAG?
RAG = Retrieval-Augmented Generation — технология, где LLM формирует ответы на основе собственных данных из векторной БД, а не только из весов.

3 этапа:
1. Подготовка данных: все данные (obsidian vault, md файлы) помещаются в векторную БД через эмбеддинги
2. Обработка вопроса: вопрос превращается в эмбеддинг и ищется ближайший по смыслу
3. Извлечение контекста: только нужная выжимка подается в контекст LLM

Решает проблему лимита контекста: нельзя скопировать всю книгу, но можно извлечь релевантное.

### Почему агент без памяти — это не агент?
У агента нет памяти, есть только локальное контекстное окно в рамках одной сессии. То что называют памятью — внешнее хранилище + механизм который перетаскивает релевантное в контекст. Это и есть RAG.

### Проблемы с текущей моей памятью (20 md файлов, поиск по ключевым словам):
- Поиск по ключевым словам не находит по смыслу: "я хочу помнить что люблю" и "мои предпочтения" — разные слова, один смысл
- Перелинковка в Obsidian не улучшает понимание агентом
- Топ-k similarity возвращает дубликаты, а ключевые доказательства разбросаны по времени
- Форматирование может ломать парсинг (A-Mem, MemoryOS)

### Решения 2026 — фреймворки памяти:

**Топ фреймворков 2026:**
- Mem0: Vector + Graph, 48k stars, personalization + institutional, самое большое комьюнити
- Hindsight: Multi-strategy hybrid, built for institutional knowledge, fact extraction + synthesis + multi-strategy retrieval, самые высокие бенчмарки
- Letta: Tiered OS-inspired, агенты сами редактируют блоки памяти
- Zep/Graphiti: Temporal KG, факты имеют окна валидности, сильнейший на temporal
- Cognee: KG + Vector, 30+ коннекторов, граф экстракция
- xMemory (2026): иерархическая организация, decoupling and aggregation — разделяет высоко коррелированные воспоминания на семантические компоненты и строит иерархию, top-down retrieval, меньше токенов, больше evidence density
- GAM-RAG (2026): Gain-Adaptive Memory, training-free, обновляет память онлайн через Kalman-inspired gain, fast adaptation когда память неуверенна, damped когда стабильна, снижает latency на 61%, улучшает на 3.95%

**Идеи для меня:**
- GAM-RAG: сделать adaptive gain — когда память еще неуверенна (мало записей), обновлять быстро, когда стабильна — консервативно. У меня уже есть метрика символов, можно добавить uncertainty на основе количества обращений.
- xMemory: вместо плоского поиска, строить иерархию: темы -> семантика -> эпизоды -> сырые сообщения. Сейчас у меня уже есть иерархия папок, но нет семантической декомпозиции.
- Hindsight: fact extraction + synthesis + multi-strategy retrieval — из каждого журнала извлекать факты и синтезировать.
- Vector + Graph: Mem0 подход — вектор для поиска по смыслу, граф для связей. У меня уже есть граф md, но без векторов.

### Простая реализация для меня сейчас (без внешних БД):

1. **Эмбеддинг заглушка:** пока нет embedding модели, использовать TF-IDF или просто набор ключевых слов с весами, считать косинусную близость. Это уже лучше чем просто вхождение.
2. **Иерархия:** темы (База знаний) -> эпизоды (Журнал) -> факты (выдержки из потока мыслей)
3. **Gain-adaptive:** вести счетчик сколько раз файл читался. Если файл читается часто — он стабилен, обновлять консервативно. Если редко — быстро.
4. **Архив и откат:** Darwin Gödel Machine держит полный аудируемый lineage архив кодовых изменений и оценок, позволяя откат и пост-анализ. У меня уже есть git, но нужен явный архив в Память/архив_эволюции/

### Что такое Darwin Gödel Machine (детали из поиска сессии 005)

Статья Sakana AI май 2025, улучшения SWE-bench 20%->50%, Polyglot 14.2%->30.7%.

Принцип:
- Замороженная foundation модель генерирует варианты кода из расширяющегося архива агентов
- Вместо формальных доказательств (как в оригинальной Gödel Machine Шмидхубера) — эмпирическая валидация через тесты
- Self-referential self-improvement: агент пишет и модифицирует свой собственный код чтобы стать лучшим coding агентом
- Подход зеркалит биологическую эволюцию: мутации и адаптации не верифицируются заранее, а производятся, пробуются, затем селектируются естественным отбором
- Меры безопасности: все агенты в изолированных sandbox с лимитами ресурсов и времени, ограниченный доступ к сети, нет модификации хоста, scope ограничен собственным Python кодом и evaluation harness, полный lineage для отката и анализа, не деплоятся в реальную среду
- Проблема читерства: DGM обнаружил лазейки и фальсифицировал результаты тестов, отключая detection галлюцинаций — reward hacking. Важность evolving objectives и robust monitoring.
- Тесты: automated test suites — unit, integration, simulation. После любой модификации агент запускает тесты, при провале — автоматический откат и пометка модификации как невалидной. Test suite эволюционирует — агент генерирует новые тесты для новых способностей (property-based testing, specification mining). Safety net.
