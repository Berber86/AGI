# Эрмитаж · Парадный зал

Одна комната Эрмитажа на **Three.js + Vite**: тёмно-зелёный шелк, золочёные рамы, наборный
паркет, две хрустальные люстры, камин с малахитовым картушем и три высоких окна на Неву.
В зале шесть подлинников в высоком разрешении и две скульптуры.

Передвижения по залу нет. Вы стоите в одной из девяти точек и осматриваетесь: взгляд на
парящий медальон другой точки в течение **десяти секунд** заполняет золотое кольцо — и зал
переносит вас туда. На обычном экране это плавный проход по воздуху, в очках — золотая
вспышка и мгновенный перенос.

## Запуск

```bash
npm install
npm run dev            # http://0.0.0.0:5173
npm run build          # dist/ + сгенерированный sw.js
npm run export:static  # dist/ → play/ (пути относительные, годится для подкаталога)
npm run gate           # check + unit + build + e2e
```

Открытая сборка: `play/index.html` (в каталоге — `games/hermitage-hall/play/index.html`).

## Управление

| Где | Действие |
|---|---|
| Обычный экран | перетаскивание мышью или пальцем вращает взгляд |
| Очки | поворот головы по гироскопу; свайп — запасной вариант |
| Выбор точки | держать в центре взгляда медальон ~10 секунд |
| Очки | короткое касание — вернуть взгляд, удержание 1,2 с — выйти в меню |
| Клавиатура | `←/→/↑/↓` или `WASD` — взгляд, `Esc` — пауза |

## Как устроено

```
src/config.js    размеры зала, свет, список картин и скульптур, девять точек
src/gaze.js      направление взгляда, углы до медальона, накопление двелля
src/travel.js    плавный проход (дуга, smoothstep) и золотая вспышка для VR
src/markers.js   медальоны: шейдер кольца, золотая пыль, столб света, ореол
src/world.js     архитектура зала, материалы, камин, люстры, свет
src/artworks.js  рамы, холсты, таблички, загрузка картин и скульптур
src/vr.js        стереопара, контроллер взгляда, гироскоп и свайп
src/ui.js        стартовый экран, HUD, карточка экспоната, панели
src/main.js      загрузка, режимы, двелль, переносы, публичный API
```

Ключевые числа: зал 18 × 13 м, высота 7 м, глаза на 1,65 м, база глаз 64 мм; двелль 10 с
при допуске 6° с затуханием при уходе взгляда; перенос — `min(7.5, max(1.5, 0.55·d + 0.9))`
секунды. В стереорежиме весь HUD скрыт: в очках нет ни прицела, ни кнопок, ни подписей.

Рамы, паркет, шелк, малахит, плафон и вид из окон рисуются процедурно в `textures.js`, поэтому
в сборке нет ни одной внешней текстуры интерьера — только живопись и две сетки скульптур.

## Производительность

Было — «полное разрешение с любой дистанции»: шесть полотен 1689–2560 px постоянно
лежали в видеопамяти (около 90 МБ), а над каждым полотном висел свой прожектор.

Стало:

- **В зале живут только миниатюры 720 px.** Файл высокого разрешения скачивается, когда
  вы подошли к точке, и сразу уменьшается до 2048 px по длинной стороне (1536 — на
  телефоне, 1024 — на лёгкой графике). Декодирование идёт в `createImageBitmap`,
  поэтому браузер не держит полный JPEG в памяти.
- Крупных текстур в памяти не больше двух: при переходе к следующей картине предыдущая
  освобождается (`.dispose()`), а пока копится кольцо двелля, текстура уже качается.
- **Восемь источников света вместо четырнадцати**: прожекторы над полотнами заменены
  светящейся трубкой, пятном на стене и несветящимся в шейдере материалом холста
  (`MeshBasicMaterial`), камин освещает угли и пятно на полу.
- **Меньше draw call**: брусья рам, карманы, подсветка и пятна света шести картин
  слиты в общие сетки (36 вызовов → 4), рама — три бруса вместо восьми.
- **Адаптивное разрешение**: DPR ограничен 1,5 (в VR — 0,95), при падении ниже 45 FPS
  внутренний масштаб уменьшается шагами до 0,62 (в VR до 0,5), при устойчивых 58+
  возвращается обратно. Если и минимальное разрешение не держит 26 FPS, качество само
  переключается на лёгкое.
- **На телефоне по умолчанию лёгкая графика**: без теней и MSAA, процедурные текстуры
  мельче, у медальонов нет столбов света и ореолов. Высокое качество остаётся в настройках.
- Стартовый экран рисуется 14 раз в секунду, а не 60: сцена за ним статична.

На SwiftShader в песочнице медиана кадра упала с 3,4 до 1,8 мс на высокой графике и до
0,6 мс на лёгкой; draw calls в общем плане — с 98 до 67. Это не замер телефона: реальный
FPS на Android по-прежнему нужно проверить на устройстве.

## Проверки

```bash
npm test                       # 19 юнит-тестов логики (углы, двелль, перенос, качество)
npm run test:e2e               # Puppeteer: 29 проверок на запущенном сервере
node tests/shot.mjs <url> <tag>  # серия кадров в evidence/screenshots/<tag>
```

E2E проверяет, что в зале только миниатюры 720 px, а деталь подгружается по требованию
(и не вверх ногами), отсутствие ошибок консоли,
накопление двелля за 9,98 с, прибытие точно в координату, длительность прохода, работу свайпа,
стереопару (оба глаза непустые, HUD отсутствует) карточку экспоната и бюджет источников света. Последний прогон —
29/29 на production-сборке из подкаталога.

`evidence/reports/e2e.json` — машинный отчёт, `evidence/screenshots/` — кадры.

## Что проверено, а что нет

Проверено в headless Chromium на SwiftShader и на production-сборке: загрузка, геометрия
взгляда, двель, переносы, стереопара, отсутствие ошибок, работа из подкаталога, офлайн-кэш,
ленивая подгрузка полотен и число источников света. Замеры SwiftShader не заменяют FPS
телефона.

**Не проверено на живом устройстве.** В песочнице нет телефона и очков, поэтому остаются
неподтверждёнными: знак наклона гироскопа на конкретной модели Android, реальный FPS на
мобильном GPU (SwiftShader даёт 0,5–15 FPS и ничего не говорит о телефоне), комфорт яркости
в линзах и поведение полноэкранного режима при добавлении на домашний экран. Если картинка
в очках «уезжает» при повороте головы — инвертируйте знак в `src/vr.js` (одна константа),
это единственное место, где возможна ошибка ориентации.

## Публикация

`play/` — самодостаточная сборка с относительными путями, манифестом, иконками и service
worker: код кэшируется версией сборки, живопись и скульптуры — в отдельном кэше, чтобы
обновление не перекачивало 4 МБ медиа. Регистрация service worker включается только в
production-сборке.
