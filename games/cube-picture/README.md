# Кубик-картинка 📷

Детская игра (3–5 лет, без текста): **телефон показывает картинку из 3–10 цветных кубиков →
ребёнок выкладывает её на столе из настоящих кубиков → фотографирует → игра проверяет сборку
и, если всё верно, картинка оживает.**

Играть: `games/cube-picture/index.html` (нужен HTTPS или localhost — иначе браузер не даст камеру;
GitHub Pages подходит).

## Как играть

1. На карте выбрать картинку (следующая непройденная покачивается).
2. Образец + ряд «что понадобится» (столько маленьких кубиков каждого цвета, сколько нужно).
3. Кнопка 📷 → камера с рамкой. Выложить кубики на **светлом однотонном фоне** (лист бумаги)
   и снять **сверху**, чтобы все кубики были внутри рамки.
   Когда игра «видит» верную сборку, рамка и кнопка затвора становятся зелёными.
4. Проверка → **оживление** + звезда, или экран «почти»: неверные кубики обведены красным
   на фото (в углу — кубик нужного цвета или ✕ «здесь пусто») и на образце.

Повёрнутая на 90°/180°/270° сборка засчитывается. Проиграть нельзя.

Меню для взрослых — **удерживать шестерёнку 1 секунду**: советы по съёмке, звук, сброс звёзд.
Если камера недоступна (запрет, старый браузер), подсвечивается кнопка с картинкой —
можно снять системной камерой или выбрать фото из галереи.

## Палитра

По умолчанию: красный, оранжевый, жёлтый, зелёный, синий, фиолетовый — `src/pictures.js` → `PALETTE`.
`hue` — оттенок (0–360), как его видит камера; необязательный `sat` (0–1) нужен, чтобы различать
близкие оттенки (например, розовый и красный). Чтобы добавить цвет — добавить запись в `PALETTE`
с новой буквой и использовать её в `rows` картинок. В тестах уже проверен вариант с розовым.

## Как работает проверка (`src/vision.js`)

Без ML и без сети, ~10 мс на снимок:

1. Кадр «рамка + поле 14%» уменьшается до 160 px (усреднение = шумоподавление).
2. Фон = медиана цвета по краю кадра; при светлом фоне выравнивается баланс белого (тёплая лампа).
3. Пиксель — кубик, если заметно отличается от фона, насыщен и не тёмный; цвет — ближайший в палитре.
4. Связные области: выкидываются крошки и всё, что касается края кадра (рука, игрушки).
5. Наклон раскладки — по направлениям краёв кубиков (усреднение `cos 4θ, sin 4θ` градиента).
6. Рамка кубиков делится на сетку картинки в 4 поворотах; в центре каждой клетки голосование за цвет.
7. Выбирается поворот с наименьшим числом ошибок; засчитывается только полное совпадение.

## Проверки

```bash
node games/cube-picture/tests/vision.test.mjs   # 467 проверок распознавания на синтетических фото
python3 -m http.server 8899 &                   # из корня репозитория
node games/cube-picture/tests/e2e.mjs           # headless Chromium (см. references/headless-browser-setup.md)
```

`vision.test.mjs` для каждой картинки: верная сборка (прямо, повороты 90/180/270, наклон до 35°,
деревянный стол, серый стол, тёплый/холодный свет, шум, мелкие кубики, неаккуратная раскладка
с зазорами, съёмка под углом, рука у края, крошка, «всё сразу»), каждый кубик по очереди другого
цвета (ошибка должна указываться ровно в этой клетке), убран, белый; лишний кубик; пустой стол;
ни одна картинка не засчитывается за другую.

`e2e.mjs` — фейковая камера Chromium показывает видео со сборкой: живой предпросмотр узнаёт её,
снимок засчитывается, звезда сохраняется; ошибка и пустой стол; все 8 анимаций (кадры меняются);
пауза камеры при сворачивании; запасной путь «фото из файла» при запрещённой камере; меню взрослых
по удержанию; отсутствие текста на детских экранах и ошибок в консоли; скриншоты 360×800 и 412×915
в `.studio/evidence/`.

## Ограничения

- Кубики должны лежать плоско одним слоем; башни/LEGO не поддерживаются.
- Белые/чёрные/коричневые кубики пока не распознаются (не входят в палитру); пёстрый фон
  (узорная скатерть) мешает — нужен однотонный.
- Проверено на синтетических снимках и фейковой камере; на реальном телефоне с реальными кубиками
  ещё не проверялось — палитра подстроится после фото кубиков.
