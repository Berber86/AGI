# Кубик-картинка 📷

Детская игра (3–5 лет, без текста): **телефон показывает картинку из 3–10 цветных кубиков →
ребёнок выкладывает её на столе из настоящих кубиков → фотографирует → игра проверяет сборку
и, если всё верно, картинка оживает.**

Играть: `games/cube-picture/index.html` (нужен HTTPS или localhost — иначе браузер не даст камеру;
GitHub Pages подходит).

## Как играть

1. На карте выбрать картинку (следующая непройденная покачивается).
2. Образец + ряд «что понадобится» (столько маленьких кубиков каждого цвета, сколько нужно).
3. Кнопка 📷 → камера с рамкой. Выложить кубики на **светлом однотонном фоне** (лист бумаги)
   и снять **сверху**, чтобы все кубики были внутри рамки.
   Когда игра «видит» верную сборку, рамка и кнопка затвора становятся зелёными.
4. Проверка → **оживление** + звезда, или экран «почти»: неверные кубики обведены красным
   на фото (в углу — кубик нужного цвета или ✕ «здесь пусто») и на образце.

Повёрнутая на 90°/180°/270° сборка засчитывается. Проиграть нельзя.

## Два режима (переключатель на карте, без текста)

- **Разноцветные кубики — «цвета и форма»**: нужно повторить и форму, и цвета.
- **Серые кубики — «только форма»**: образец нарисован серыми кубиками «любого цвета»; подходит любой
  цвет наших кубиков (и голубой, и сиреневый). Картинка оживает **в тех цветах, из которых её собрал
  ребёнок**. Лишний или недостающий кубик подсвечивается как обычно.

У каждого режима свои звёзды.

Меню для взрослых — **удерживать шестерёнку 1 секунду**: советы по съёмке, звук, **допуск цвета**
(широкий — по умолчанию, или строгий), сброс звёзд.
Если камера недоступна (запрет, старый браузер), подсвечивается кнопка с картинкой —
можно снять системной камерой или выбрать фото из галереи.

## Палитра

Настроена по фото настоящих кубиков (`src/pictures.js` → `PALETTE`), экран калибровки не нужен:

| Буква | Цвет | Как видит камера (отн. серого листа) |
|---|---|---|
| `Y` | жёлтый | 1.15 · 0.88 · 0.39 |
| `R` | красный | 1.12 · 0.54 · 0.60 |
| `K` | розовый | 0.97 · 0.48 · 0.67 |
| `P` | фиолетовый | 0.61 · 0.46 · 0.65 |
| `G` | зелёный (тёмный) | 0.40 · 0.52 · 0.47 |
| `B` | тёмно-синий | 0.30 · 0.37 · 0.62 |
| `C`, `L` | голубой, сиреневый — «двойники» | есть в наборе, в картинках не используются |

`rel` — цвет кубика, делённый на цвет фона (R·G·B). Голубой и сиреневый игра узнаёт: при **широком**
допуске они засчитываются за синий и фиолетовый (`twin`), при **строгом** — нет.

## Допуск цвета

**Широкий (по умолчанию)** — для «неудобного» света:
- подстройка под снимок: по кубикам на фото оценивается, насколько телефон усилил/приглушил цвета и
  какой оттенок остался после деления на фон (кремовая бумага, голубоватая тень, лампа), — одно
  преобразование на весь кадр, поэтому ошибку ребёнка оно не прячет;
- фон учитывается с плавным перепадом света по кадру (лампа с одной стороны, окно с другой);
- голубой = синий, сиреневый = фиолетовый; кубик, который камера видит «наполовину другим», засчитывается;
- **красный и розовый** сравниваются относительно: свет может сдвинуть оба, но «красные» клетки должны
  остаться заметно краснее «розовых». Если в картинке только красный — кубик засчитывается, пока он явно
  не розовый. Перепутанные красный и розовый по-прежнему находятся.

**Строгий** — прежнее поведение: каждый кубик должен быть близок к своему эталону.

На синтетике с трудным светом (кремовая бумага, голубоватая тень, усиленные/блёклые цвета, тоновые кривые
камеры, сильная лампа, смешанный свет) широкий допуск не засчитывает правильную сборку в 1 случае
из 384, строгий — в ~50%.
Чтобы перенастроить под другие кубики: сфотографировать их сверху на сером/белом листе, взять медиану
цвета каждого кубика, поделить на медиану листа и записать в `rel`.

## Как работает проверка (`src/vision.js`)

Без ML и без сети, ~10 мс на снимок:

1. Кадр «рамка + поле 14%» уменьшается до 160 px (усреднение = шумоподавление).
2. Фон = медиана цвета по краю кадра (при широком допуске — с плавным перепадом по сторонам, медиана
   медиан отрезков, чтобы рука на краю не мешала); каждый пиксель делится на фон.
3. Пиксель — кандидат в кубик, если заметно отличается от фона и либо окрашен, либо заметно темнее
   фона (тёмно-зелёный почти серый).
4. Цветность — в логарифмах (баланс белого = сдвиг, тоновая кривая/насыщенность = растяжение).
   Широкий допуск: подстройка `u' = g·u + t` — байесовская регрессия по средним цветам (каждый цвет —
   один голос, красный/розовый не голосуют), с притяжением к «без подстройки».
5. Общая светлота сцены (белая бумага ярче серой ткани) оценивается по уверенным пикселям; итоговый
   цвет — ближайший эталон по цветности и светлоте.
6. Заполнение «дыр» в бледных кубиках; связные области **по каждому цвету отдельно**: выкидываются
   крошки, всё, что касается края кадра (рука, складка листа), и мелкие обрывки рядом с ним.
7. Наклон раскладки — по направлениям краёв кубиков (усреднение `cos 4θ, sin 4θ` градиента).
8. Рамка кубиков делится на сетку картинки в 4 поворотах; в центре каждой клетки голосование за цвет.
9. Выбирается поворот с наименьшим числом ошибок; засчитывается только полное совпадение.

## Проверки

```bash
node games/cube-picture/tests/vision.test.mjs   # 963 проверки: синтетика + текстуры реальных кубиков
python3 -m http.server 8899 &                   # из корня репозитория
node games/cube-picture/tests/e2e.mjs           # headless Chromium (см. references/headless-browser-setup.md)
```

`vision.test.mjs` для каждой картинки: верная сборка (прямо, повороты 90/180/270, наклон до 35°,
белая бумага, серый стол, кубики ярче/темнее, настоящие текстуры кубиков с фото (`tests/fixtures-real-cubes.png`)
прямо/с наклоном/с ярким и тёплым светом, тёплый/холодный свет, шум, мелкие кубики, неаккуратная раскладка
с зазорами, съёмка под углом, рука у края, крошка, «всё сразу», трудный свет: кремовая бумага,
голубоватая тень, усиленные/блёклые цвета, тоновые кривые, сильная лампа, смешанный свет — и то же
на настоящих текстурах); строгий допуск на обычном свете; каждый кубик по очереди другого цвета
(ошибка должна указываться ровно в этой клетке — и при широком, и при строгом допуске), убран, белый;
голубой/сиреневый вместо синего/фиолетового — засчитываются при широком допуске и не засчитываются
при строгом; лишний кубик; пустой стол; ни одна картинка не засчитывается за другую.
Режим «форма»: любые цвета (в т. ч. все одного цвета, настоящие текстуры, поворот), без кубика,
лишний кубик, пустой стол, чужие формы не засчитываются.

`e2e.mjs` — фейковая камера Chromium показывает видео со сборкой: живой предпросмотр узнаёт её,
снимок засчитывается, звезда сохраняется; ошибка и пустой стол; все 8 анимаций (кадры меняются);
пауза камеры при сворачивании; запасной путь «фото из файла» при запрещённой камере; меню взрослых
по удержанию и переключатель допуска; режим «форма» (свои звёзды, ракета из любых цветов засчитана
и оживает, без кубика — ошибка в одной клетке); отсутствие текста на детских экранах и ошибок в консоли; скриншоты 360×800 и 412×915
в `.studio/evidence/`.

## Ограничения

- Кубики должны лежать плоско одним слоем; башни/LEGO не поддерживаются.
- Нужен **светлый нейтральный** однотонный фон (белая бумага, серый лист). Деревянный/цветной стол
  сдвигает цвета (красный уходит в розовый) — не поддерживается; пёстрая скатерть мешает.
- Белые/чёрные/коричневые кубики не распознаются (не входят в палитру).
- Сиреневый кубик на **сером** столе камера видит почти серым, как тень, — в режиме «форма» его лучше
  выкладывать на белой бумаге.
- Широкий допуск может засчитать розовый вместо красного в картинках, где розового нет (светофор, ракета),
  если свет сильно сдвинул цвета; для точной проверки — строгий допуск.
- Палитра проверена на текстурах с реального фото кубиков и синтетике; живой прогон на телефоне
  с камерой ещё не делался.
