# Стенд задержки «телефон-джойстик» — как пользоваться

Стенд отвечает на один вопрос: **хватит ли Firebase Realtime Database по
задержке на ваших двух телефонах с вашим VPN**, или режиму «экран + джойстик»
для Candy Kingdom Coaster нужен WebRTC. Контракт — `../JOYSTICK_BRAINSTORM.md`.

## Быстрая проверка без Firebase (2 минуты)

1. Откройте `index.html` в браузере (любой статический сервер или превью).
2. Нажмите «Демо в двух вкладках», в первой вкладке — «Экран», во второй —
   «Джойстик», введите код комнаты с экрана.
3. Нажимайте ◀ ▶: экран показывает руль, пинг собирается сам. Задержка здесь
   почти нулевая — это проверка интерфейса, а не сети.

## Настоящий замер через Firebase (10 минут)

Нужен свой бесплатный проект Firebase (карточка не требуется):

1. [console.firebase.google.com](https://console.firebase.google.com) →
   «Add project», имя любое, Analytics можно выключить.
2. В проекте: **Build → Realtime Database → Create Database**. Локация —
   `europe-west1` (Бельгия), режим — **Start in test mode**.
3. **Project settings (шестерёнка) → Your apps → Web (`</>`)** → зарегистрируйте
   приложение, Firebase покажет `firebaseConfig`. Скопируйте весь объект.
4. Откройте стенд на обоих телефонах (оба — с включённым VPN, как в реальном
   сценарии), вставьте конфиг на обоих, «Подключить Firebase».
5. Телефон-экран: «Создать комнату» → покажет 6-значный код.
   Телефон-джойстик: «Ввести код» → код → руль.
6. Поиграйте кнопками пару минут. Смотрите «Замеры»: медиану «в одну сторону»
   и вердикт стенда. Критерий из контракта: **медиана ≤ 300 мс — делаем режим
   на Firebase; стабильно хуже — проектируем WebRTC**.

## Про трафик

Джойстик пишет только нажатия/отпускания + пинг раз в 2 с + статистику.
Заезд — сотни килобайт. Бесплатный Spark даёт Realtime Database 10 ГБ
скачивания в месяц — стенд и будущий режим израсходуют крохи. Firestore
стенд не использует намеренно: у него лимит 20 000 записей в день.

## Безопасность (важно)

Для стенда используется test mode базы: комнатой может управлять любой,
кто знает код и конфиг проекта. Это нормально для личного замера, но:

- не публикуйте ссылку на стенд вместе с конфигом рабочего проекта;
- после замеров удалите базу или закройте правила (Rules →
  `{ "rules": { ".read": false, ".write": false } }`);
- для боевого режима понадобятся нормальные правила и анонимная
  авторизация — это часть отдельной разработки, не стенда.

## Что означают цифры

- **Задержка события** — сколько ехало последнее нажатие до экрана
  (по серверному времени Firebase, часы телефонов не влияют).
- **Пинг-понг RTT** — туда-обратно джойстик→экран→джойстик; реальная
  задержка нажатия ≈ RTT/2, её медиану и p95 стенд и показывает.
- **p95** — «плохой случай»: 5% нажатий будут медленнее этого значения.
  Смотрите и на неё: редкие всплески под VPN нормальны.
