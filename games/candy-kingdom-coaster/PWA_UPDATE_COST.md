# «Снова тормоза»: почему после обновления и что исправлено

Жалоба владельца (2026-10-17, после раунда с двумя метками): «снова возникли
тормоза в игре. Почему?» Речь о рывках **сразу после обновления**; в стационарной
игре их не было.

## 1. Виноват не рендер и не камера

Стенд A/B: текущий `c5e2194` против базы `e474c8c` (до правок двух меток), одна
и та же сцена, SwiftShader, dpr 1.

| Что | `c5e2194` | база `e474c8c` |
|---|---|---|
| JS на кадр: обычная / VR / VR+камера, мс | 0.59 / 0.84 / 1.01 | 0.67 / 0.75 / 1.18 |
| анализ кадра меток: dual / single, мс | 0.28–0.30 / 0.135–0.147 | 0.29–0.31 / 0.141–0.148 |
| draw calls / triangles (VR) | 924 / 1.887 M | 924 / 1.888 M |
| programs / geometries / textures | 197→199 / 437 / 87 | столько же |
| взгляд на шумном детекторе, 52 кадра | bigJumps 6, p95 7.0° | 7, 8.2° |

Профиль CPU (CDP, 6 с): 7028 мс против 7787 мс, ~98 % — программный OpenGL
стенда (`getProgramInfoLog`/`getShaderInfoLog`), `camtrack.js` — 6 мс. Прирост
кода в раунде (11 файлов) не добавил ни одного `setInterval`/`requestAnimationFrame`.

Вывод: **стационарная производительность не изменилась**. Рывки даёт загрузка,
которая идёт ровно после каждого обновления.

## 2. Причина: один версионный кэш на 7.3 МБ

PWA-кэш был одним бакетом `ckc-vNN` из **87 файлов / 7.3 МБ**, куда входили и код,
и медиа. Смена версии в `sw.js` (а она меняется каждый раунд) на install-е
заново скачивала **все 87 файлов**, включая 5.82 МБ неизменных картинок
(`icon-512.png` 2.45 МБ, `lily.png` 1.87 МБ и т. д.). На телефоне это совпадает
с первым запуском после обновления — сеть и декодирование конкурируют с первым
кадром, игра «тормозит». Плюс `cache.addAll` атомарен: один 404 — и офлайн-кэш
не собирается вовсе.

## 3. Что сделано (`sw.js`, раздельные кэши)

Два кэша с разным жизненным циклом:

- `CACHE = 'ckc-v48'` — только код и оболочка: **53 записи / 1.47 МБ**. Меняется
  с каждым обновлением игры.
- `MEDIA_CACHE = 'ckc-media-v1'` — картинки/текстуры/шрифты: **34 файла /
  5.82 МБ**. Качается один раз и **переживает смену версии**; версия медиа
  поднимается только при реальной замене ассетов.

Детали:

- `precache()` кладёт файлы по одному (не `addAll`) и **не перекачивает уже
  лежащее** — повторная установка медиа стоит 0 запросов.
- Неполный precache кода (<90 % файлов, оборвалась сеть) **валит install**:
  старый service worker и его рабочий офлайн-кэш остаются.
- `/assets/` — cache-first в `MEDIA_CACHE`; музыка (`/assets/music/`) —
  network-first, чтобы новый mp3 подхватывался, а офлайн играл из кэша.
- При активации удаляются только чужие кэши; `ckc-media-v1` не трогается.

## 4. Замер стоимости обновления

`tests/tools/updatecost.mjs` поднимает игру, ставит SW, затем подменяет версию
(текущая → следующая; номер берётся из `sw.js`) и считает запросы/байты:

```
первая установка: {'ckc-v48': 53, 'ckc-media-v1': 34}
после обновления: {'ckc-media-v1': 34, 'ckc-v49': 52}
обновление: медиа 0 файлов / 0.00 МБ, код 52 файла / 1.47 МБ
итого обновление: 1.47 МБ
```

Было 7.3 МБ каждый раз → стало 1.47 МБ, и это только код, который всё равно
нужен новой версии.

Оговорка: **первый** переход на схему с раздельными кэшами с телефона, где
ещё лежит старый единый бакет (`ckc-v45` и раньше), будет стоить как раньше —
7.3 МБ: медиа-кэш `ckc-media-v1` создаётся с нуля. Со второго обновления
платится только код (1.47 МБ); номер версии растёт каждый релиз. (52, а не 53, — это счётчик тестового сервера: `./` и
`./index.html` один файл; в реальном кэше 53 записи.)

## 5. Офлайн не сломан

`tests/tools/pwaqa.mjs` — 4/4: код и медиа в разных кэшах, в кэше кода нет
медиа, медиа-кэш собран при установке, **офлайн-перезапуск доходит до ready**.

`uiqa` дополнен двумя проверками (медиа ищется по всем кэшам, а в версионном
кэше его быть не должно): 25/25, `--offline` — 26/26 (в т. ч. реальный офлайн-
перезапуск с иллюстрированным экраном).

## 6. Как воспроизвести

```bash
cd games/candy-kingdom-coaster
node tests/tools/pwaqa.mjs            # 4/4 — архитектура кэша + офлайн
node tests/tools/updatecost.mjs       # стоимость обновления версии
```

Стационарные метрики — `tests/tools/perfcam.mjs`, `cprof.mjs` (см. таблицу §1).
