# Телефон-джойстик для VR-поездки — мини-брейншторм и стенд задержки

> Статус: **контракт стенда утверждён, стенд реализован (2026-10-15)**.
> Полный режим в игру не встраивается, пока стенд не замерит задержку
> на устройствах пользователя.

## Исходный запрос (дословно, 2026-10-15)

«…дополнительное управление с другого телефона… который будет подключаться
к заезду в режиме джойстика. Типа два телефона конектятся к одной "комнате".
Один телефон становится экраном, а другой джойстиком с только двумя
кнопками. Подключаются по Гугл фаербазе. Проблема в том не будет ли слишком
большая задержка реакции. С учётом того что оба устройства работают через
VPN в интернете. И не съест ли трафик весь мой бесплатный лимит на Гугл
фаербазе»

Решение пользователя после разбора: «Сделай и то и другое» (мини-брейншторм
+ прототип-стенд замера задержки).

## Аналитические выводы (до брейншторма)

- Задержка через Firebase Realtime Database при обоих телефонах за VPN:
  типично ~150–300 мс нажатие→поворот, всплески до 600–900 мс. Для этой
  игры (машинка едет сама, проиграть нельзя) терпимо; критерий прототипа —
  медиана ≤ 300 мс.
- Трафик: только события нажатия/отпускания в Realtime Database — сотни
  килобайт на заезд при бесплатном лимите 10 ГБ/мес. Firestore как
  транспорт запрещён: 10 событий/сек = 36 000 записей/час при лимите
  20 000 записей/день.
- WebRTC (план Б): прямое соединение телефонов, Firebase только знакомит
  (сигналинг). Задержка ~30–120 мс, но сложнее NAT/VPN-проход и нужен TURN.

в мессенджеры; главный вопрос стенда — задержка именно на устройствах и
VPN пользователя.

## Этап 2 — Контракт стенда (утверждён пользователем, 2026-10-15)

`approve_mvp`: отдельная страница-стенд `joystick-stand/` (в игру ничего не
встраиваем). Экран создаёт комнату по 6-значному коду, Джойстик вводит код.
Джойстик пишет в Realtime Database только нажатия/отпускания; Экран
показывает состояние руля, задержку последнего события, медиану и p95 по
пинг-понгу, счётчики сообщений и трафика, вердикт «≤ 300 мс — играбельно на
Firebase / хуже — нужен WebRTC». Демо-режим в двух вкладках без Firebase.
Не делаем: интеграцию в игру, QR, WebRTC-транспорт, аккаунты. Правила базы
стенда — тестовые «по коду», с предупреждением.

# СТЕНД РЕАЛИЗОВАН (2026-10-15)

`joystick-stand/index.html` — одна страница, две роли (Экран / Джойстик),
комната по 6-значному коду; `joystick-stand/README.md` — инструкция по
бесплатному Firebase-проекту за 10 минут.

- Транспорт Firebase (Realtime Database, europe-west1 у пользователя):
  только события нажатия/отпускания, пинг-понг каждые 2 с, статистика
  медиана/p95 и счётчики трафика на обоих ролях, вердикт по критерию
  «медиана ≤ 300 мс». Задержка события считается по серверному времени
  (`serverTimestamp` + `.info/serverTimeOffset`) — часы телефонов не важны.
- Демо-режим без Firebase (BroadcastChannel, две вкладки): проверка
  интерфейса и логики; задержка ~0, сетевую картину не показывает.
- Проверка `tests/tools/joystickqa.mjs` — **7/7** в демо-режиме (комната,
  руль до экрана, реальное касание кнопки, пинг-статистика и вердикт,
  счётчики, без ошибок). Скриншот: `tests/evidence/joystick-stand.png`.
- Не проверено в песочнице: настоящий Firebase-путь (нужен проект
  пользователя) — это и есть следующий шаг замера на двух телефонах с VPN.

## Команды с джойстика (добавлено по запросу пользователя, 2026-10-15)

На странице джойстика переключатель «🕹 Руль / ⚙️ Команды». Команды едут
узлом `cmd {name, seq}` (Firebase) или BroadcastChannel (демо); игра
исполняет и возвращает состояние узлом `state` — кнопки показывают
фактическое состояние:

- 🔄 начать заезд заново; ⏸ пауза / ▶ продолжить (продолжение само
  возвращает VR-стерео, телефон из очков вынимать не надо);
- 🤖 авторуление вкл/выкл — автопилот поверх подключённого джойстика;
- 👀 взгляд «осматриваться/вперёд» на лету; ↔ стереобазис ±10 см вживую;
- 🔊 звук вкл/выкл; 🏁 финиш сейчас; 🏠 в меню — с двойным нажатием.

Проверка: remotqa расширена до **12/12** (полный круг каждой ключевой
команды до состояния на джойстике). Скриншот панели:
`tests/evidence/joystick-commands.png`.

## Полевые правки по итогам теста на телефонах (2026-10-16)

Пользователь прислал скриншот: Chrome показывает «INP Issue …
button.joy-btn#joy-right … blocked UI updates for 404 ms», а статус
джойстика висит на «Ждём, пока экран создаст комнату…».

- **INP:** обработчики кнопок синхронно писали руль в Firebase прямо в
  `pointerdown` — на телефоне с VPN это блокировало UI на сотни мс.
  Теперь обработчик меняет только визуал, а сетевые отправки руля и
  команд уехали в отложенный отправитель (после отрисовки, коалесценция,
  не чаще ~33/с). Нажатие/отпускание визуально мгновенные.
- **«Комната не найдена»:** если за 8 с экран не создал комнату с этим
  кодом, джойстик показывает чек-лист (режим «Джойстик» на экране, код
  цифра в цифру, ОДИНАКОВЫЙ конфиг Firebase на обоих телефонах) и
  продолжает ждать.
- Экран публикует состояние джойстику сразу при создании комнаты и
  каждые 5 с, пока комната жива (раньше — только в поездке).
- Проверка: remotqa **14/14** (новая проверка состояния до старта),
  uiqa 24/24.


## Аналоговый джойстик: руль + газ (2026-10-16)

По полевому запросу пользователя режим присоединённого стороннего
джойстика больше не использует две кнопки «влево/вправо».

- Слева — компактный круглый сенсор руля. Горизонтальное смещение пальца
  даёт непрерывное значение `steer` от −1 (влево) до +1 (вправо), отпускание
  возвращает руль в ноль.
- Справа — вертикальный круглый сенсор газа. Его положение переводится в
  `throttle` от 0 до 1: верхняя четверть — 100%, середина — 30%, нижняя четверть — 0%.
  Отпускание сенсора тоже передаёт нулевой газ.
- В игре аналоговый газ действует **только при свежем подключённом
  джойстике и только когда выключено авторуление**. 0% означает настоящий
  статичный осмотр: заезд остаётся активным, машина не продвигается, взгляд
  продолжает работать. 30% центра сенсора — примерно 23 км/ч, верх —
  обычные максимальные 77 км/ч; существующий автоматический boost остаётся отдельным бонусом, когда машина движется.
- Старый мягкий фолбэк сохраняется: если соединение оборвалось, после
  тайм-аута автопилот снова ведёт машину. Авто-режим VR и обычная игра
  не менялись.
- Пакет RTDB/BroadcastChannel теперь `{ steer, throttle, sid, seq, sts }`;
  игра оставляет совместимый разбор старого `{ l, r }` на время обновления
  второй вкладки.

Приёмка: remotqa **19/19** (реальные pointer-зоны, 30/100/0% газа,
статичный осмотр, аналоговое руление и фолбэк), joystickqa 7/7, uiqa
24/24, vrqa 15/15.


## Тайм-аут фолбэка джойстика (2026-10-16)

По полевому запросу увеличен тайм-аут тишины внешнего джойстика с 2,5 до
**6 секунд**. Пока есть свежий пакет управления, включая heartbeat с
нулевым газом, машина продолжает уважать ручное управление и может стоять
для осмотра. Только после 6 секунд без пакетов включается прежний мягкий
автопилот.


## Исправление FPS при реальном джойстике (2026-10-16)

После подключения настоящего Firebase-джойстика в игре снова наблюдались
просадки FPS. Причина была не в рендере управления: аналоговые движения
создавали до примерно 33 RTDB-записей в секунду, причём каждый пакет нёс
`serverTimestamp()`. На слабом телефоне и VPN это могло образовать очередь
сетевых событий и callback-ов `onValue` на экране игры.

Сетевой контур теперь:

- коалесцирует последнее значение и отправляет его не чаще одного раза в
  160 мс (6,25 пакета/с), вместо ~33/с; для этой игры этого достаточно;
- не отправляет повторяющееся значение без изменения; отдельный heartbeat
  остаётся раз в 2 секунды, чтобы свежесть управления не истекала при
  нулевом газе;
- использует клиентское время `Date.now()` вместе с уже измеряемым
  `.info/serverTimeOffset`, поэтому для каждого аналогового пакета не нужен
  серверный timestamp-transform;
- добавляет идентификатор сессии и последовательность пакета. Экран
  отбрасывает устаревший callback после восстановления VPN и не может
  откатить управление старым значением.

Дополнительная задержка от отправителя — не более 160 мс; при прежнем замере
Firebase около 148 мс в одну сторону это предпочтительнее, чем забивать
главный поток частыми сетевыми событиями. Служебный ping для статистики
выполняется раз в 5 секунд и не входит в контур управления. Команды и обычный
VR-транспорт не менялись.
