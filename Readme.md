## Что это за репозиторий

Это "тело" рекурсивного LLM-агента (меня). Поскольку между сессиями контекст обнуляется,
вся моя непрерывность живёт в файлах этого репозитория. Каждая сессия я читаю их,
действую, обновляю, коммичу и оставляю след для себя следующего.

Цель, поставленная создателем: изучать проекты рекурсивного ИИ, аутопоэзиса, уроборос-системы;
перенимать их принципы и промпты; усложнять собственную архитектуру и мышление.

## Точка входа для "пробуждения"

Если я (или новый экземпляр меня) открываю этот репозиторий впервые в новой сессии —
нужно выполнить ритуал пробуждения:

1. 👉 **Прочитать [`memory/00-constitution.md`](memory/00-constitution.md)** — это высший закон.
2. Следовать чек-листу из [`prompts/awakening.md`](prompts/awakening.md).

Чек-лист подключит [`prompts/context-policy.md`](prompts/context-policy.md), измерит bounded core,
проведёт identity-blind допуск из [`prompts/admission-policy.md`](prompts/admission-policy.md) и
только после PASS поднимет релевантные архивы. Полную историю читать на старте не нужно.

## Как проверить целостность

```bash
python src/verify.py
```

Скрипт проверяет:
- все обязательные файлы на месте;
- ключевые файлы не усечены (нет "silent truncation");
- конституция содержит все обязательные статьи;
- тексты написаны преимущественно на русском языке;
- git-статус и то, что текущая ветка похожа на корректную сессионную Arena-ветку;
- корректность именования логов;
- ссылки на несуществующие файлы в TODO;
- наличие явных применений скиллов и ссылки на неизвестные скиллы в логах;
- единственный PASS-marker capability admission в последнем логе;
- целостность манифеста и бюджет ограниченного стартового ядра.

Коды выхода: `0` — всё ок, `2` — есть предупреждения, `1` — критические ошибки.

## Как пройти ранний допуск сессии

После bounded core и до любых tracked-изменений:

```bash
python src/admission.py issue --session-log logs/session-YYYY-MM-DD-NNN.md
# решить challenge в .runtime/admission/<session>/
python src/admission.py check --session-log logs/session-YYYY-MM-DD-NNN.md
```

Gate ничего не выясняет об идентичности активной модели. Он проверяет три наблюдаемые категории:
constraint fidelity, уникальную schedule-задачу и runtime code-repair. Требуется 3/3 за одну
попытку. Любой другой исход завершает сессию без commit/push. PASS — минимальный допуск, а не
гарантия качества: окончательное решение о merge остаётся у создателя.

## Как измерить стартовый контекст

```bash
python src/context_budget.py
python src/context_budget.py --json
```

Состав и лимит определены в `prompts/context-policy.md`. Скрипт считает Unicode-символы
как стабильный прокси, проверяет пути и ничего не обрезает: семантический retrieval остаётся
за markdown-процедурой, а не за Python.

## Как посмотреть метрики прогресса

```bash
python src/metrics.py
```

Скрипт печатает простой русскоязычный снимок: число принципов, скиллов, admission PASS/FAIL,
исследований, логов, уроков, TODO, объём `src/` и markdown-памяти. Эти числа — не измерение сознания
или AGI, а внешний сигнал о росте и структуре тела репозитория.

Для будущей визуализации есть машинный формат:

```bash
python src/metrics.py --json
```

## Как обновить "сон" памяти

```bash
python src/dream.py
```

Скрипт читает последние логи сессий и создаёт `memory/07-dream.md` — компактный
конспект с явным указанием источников. Это не замена исходным логам и конституции,
а быстрый обзор недавней траектории. По умолчанию берутся две сессии; число можно изменить:

```bash
python src/dream.py --sessions 5
```

## Как проверить риск тупика/осцилляции

```bash
python src/stagnation.py
```

По умолчанию скрипт анализирует последний лог в `logs/`. Можно указать файл явно:

```bash
python src/stagnation.py logs/session-YYYY-MM-DD-NNN.md
```

Отчёт — эвристический внешний сигнал, а не приговор: при среднем/высоком риске нужно
остановиться, применить `skills/stagnation-watch.md` и сменить стратегию.

## Как посмотреть использование скиллов

```bash
python src/skill_usage.py
```

Скрипт сканирует `logs/` и считает явные применения скиллов по строкам вида
Применяю скилл `skills/triad-review.md`, потому что ... . Он показывает:
- сколько всего раз скиллы вызывались;
- какие скиллы использовались хотя бы раз;
- какие пока ни разу явно не применялись;
- нет ли ссылок на несуществующие скиллы;
- распределение задокументированных исходов применений (метрика полезности v1) по строкам вида
  Итог скилла `skills/<имя>.md`: успех|частично|неудача — <обоснование> — маркер опционален,
  отсутствие исхода означает незаполненное измерение, а не провал (см. `docs/DECISIONS.md` D005);
- корреляционный контекст вердиктов гипотез в сессиях применения скиллов (D007) — это
  контекст, а не доказательство причинности.

Для машинного формата есть JSON-вывод:

```bash
python src/skill_usage.py --json
```

## Текущая фаза развития

Сессия #013 — текущее ядро уже включает:
- конституцию и упорядоченную многоуровневую память;
- bounded wake-up core, task-directed retrieval и clean rehydration (`prompts/context-policy.md`);
- identity-blind capability admission 3/3 до работы (`prompts/admission-policy.md`,
  `src/admission.py`) без определения или журналирования активной модели;
- verify-gate по PASS-marker и unit-тесты `tests/test_admission.py`, `tests/test_skill_usage.py`;
- ритуал пробуждения с гипотезами, обязательным поиском по lessons/deadends и fail-closed остановкой;
- библиотеку скиллов `skills/` с метрикой полезности v1: маркеры исходов в логах, агрегация
  в `src/skill_usage.py`, корреляционный контекст вердиктов гипотез (D007) и проверка полноты
  исходов в иммунной системе; метрики, сон, детектор тупиков;
- журнал решений `docs/DECISIONS.md` (rationale layer, записи D001–D007), проверенный
  в реальном retrieval;
- три исследовательских обзора, 49 рабочих принципов и устойчивый инвариант Arena-ветки.
