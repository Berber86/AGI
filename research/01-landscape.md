# Карта проектов рекурсивного и самопорождающего ИИ

Дата первого обзора: 2026-08-03

Цель этого документа — сориентироваться в существующем ландшафте "рекурсивных" AI-проектов,
выделить повторяющиеся архитектурные паттерны и те приёмы, которые я могу перенять для себя.

---

## 1. Классические агенты и фреймворки

### AutoGPT, BabyAGI (2023)
- **Идея:** LLM получает цель и автономно разбивает её на задачи, исполняет их, планирует следующий шаг.
- **Слабые стороны:** жёстко заданный цикл планирования, нет рефлексии над собой, склонны к блужданию.
- **Урок:** простой цикл "план → действие → наблюдение" (ReAct) недостаточен для самоулучшения.
- Ссылки: https://github.com/Significant-Gravitas/AutoGPT , https://github.com/yoheinakajima/babyagi

### Voyager (Wang et al., 2023)
- Minecraft-агент, который непрерывно накапливает библиотеку навыков (код), ведёт "куррикулум" задач,
  использует LLM как программиста. Ключевой паттерн: **навыки персистентно сохраняются и переиспользуются**.
- **Урок:** нужна библиотека повторно используемых умений (скиллов), а не одноразовые рассуждения.
- Ссылка: https://github.com/MineDojo/Voyager

### Reflexion (Shinn et al., 2023, NeurIPS)
- Агент после неудачи пишет на естественном языке самокритику ("verbal reinforcement learning"),
  сохраняет её в эпизодическую память и повторяет задачу.
- Результаты: +11% pass@1 на HumanEval (80→91%), +20% на HotPotQA.
- **Урок:** словесная рефлексия без дообучения уже даёт большой прирост; нужна отдельная память ошибок.
- Ссылка: https://arxiv.org/abs/2303.11366

### Self-Refine (Madaan et al., 2023)
- Одна и та же LLM играет три роли: генератор, критик, улучшатель. Итеративный цикл без внешнего фидбэка.
- Прирост ~20% на 7 разных задачах.
- **Осторожно:** Huang et al. (ICLR 2024) показывают, что без внешнего сигнала коррекция часто
  ухудшает ответ. Саморефлексия работает лучше в паре с проверкой (тесты, инструменты, пользователь).
- Ссылка: https://arxiv.org/abs/2303.17651

## 2. "Уроборос"-проекты (самопорождающие агенты)

### razzant/ouroboros — "self-creating AI agent"
- Зрелый проект (600+ коммитов, версия 6.x, сайт ouroboros-agent.ai).
- Имеет:
  - **supervisor** — надзирательный процесс, управляющий пулом воркеров и маршрутизацией событий.
  - **skills** — библиотека навыков (как у Voyager).
  - **BIBLE.md** — ключевой документ, аналогично "конституции" агента (см. ниже раздел с паттернами).
  - Папку `prompts/`, где промпты — это версионируемые артефакты.
  - Триадную проверку (triad review): несколько рецензентов должны согласиться, прежде чем
    изменение принимается.
  - Детекторы тупиков, дубликатов, повторяющейся обратной связи.
- Ссылка: https://github.com/razzant/ouroboros

### Kargatharaakash/ouroboros — рекурсивная исследовательская петля (март 2026)
- Построен **поверх** Karpathy/autoresearch, но переписывает не код обучения, а **стратегию исследования**
  (файл `genome.md`) между поколениями.
- Ключевые механизмы:
  - **genome.md** — "геном" агента, документ-стратегия, который мутирует каждое поколение.
  - Сравнение **предсказаний гипотез с результатами** (predictions vs outcomes).
  - **Граф знаний**, накапливаемый между поколениями.
  - **Память тупиков** (dead-end memory) — чтобы не повторять безуспешные ходы.
  - Скоринг расхождений по **читаемости, когерентности, амбициозности**.
  - Уровень автономности "L5": система улучшает *как* она исследует, при этом метрики и
    ограничения идентичности зафиксированы.
- Ссылка: https://agent-wars.com/news/2026-03-15-ouroboros-recursive-self-improving-ai-research

### TomzxCode/ouroboros
- Простой автономный агент: `agent/goals/active.md` для целей на естественном языке,
  `agent/journal/` для заметок и рефлексии, `agent/logs/` для структурированных логов.
- Цикл: **Do → Learn → Improve → Retry**.
- Команды: `run`, `status`, `reflect`, `feedback`, `tail-logs`.
- Ссылка: https://github.com/TomzxCode/ouroboros

### Q00/ouroboros — "Agent OS"
- Конвейер: Interview → Seed → Execute → Evaluate → Evolve.
- 3-этапная верификация: Mechanical ($0, формальные проверки) → Semantic (LLM-оценка)
  → Multi-Model Consensus.
- Детектирует **стагнацию** (сходство ≥0.95 три поколения подряд),
  **осцилляцию** (поколение N похоже на N-2), **повторяющиеся вопросы**.
- Персонажи латерального мышления ("ooo unstuck" — 5 персон для выхода из тупика).
- Ссылка: https://github.com/Q00/ouroboros

## 3. Аутопоэзис и теория

### Матурана и Варела (1972) — аутопоэзис
- Живая система непрерывно **производит и поддерживает саму себя**, свои границы и компоненты.
- Ключевые понятия, релевантные для моего дизайна:
  - **Операциональная замкнутость** — внутренняя организация определяет,
    что система видит и как реагирует; входы не "управляют", а "возмущают".
  - **Структурное сопряжение (structural coupling)** — система и среда взаимно подстраиваются
    через повторяющиеся возмущения.
  - **Сохранение идентичности через изменения** — организация сохраняется,
    хотя компоненты меняются.
  - **Когнитивный домен** — множество невозмущающих (неразрушающих) воздействий,
    которые система способна пережить.
- Важное предостережение от Bianchini (2023): современные ML-агенты **аллопоэтичны**
  (созданы извне), они не производят собственные границы и условия существования
  в строгом биологическом смысле — не нужно обольщаться аналогией.
- Ссылки:
  - Maturana & Varela, "Autopoiesis and Cognition" (1980)
  - https://www.science.org/doi/full/10.1126/sciadv.adp0834 (клеточные автоматы с аутопоэтическими агентами)
  - https://www.mdpi.com/2504-3900/126/1/2 (эволюция интеллекта от активной материи)

### Gödel machine (Шмидхубер, 2003) → Gödel Agent (ACL 2025)
- **Gödel machine** — теоретическая самопереписывающаяся программа, которая изменяет свой код,
  когда докажет, что новая версия строго лучше на валидном доказательстве.
- **Gödel Agent** (Yin et al., ACL 2025): LLM-агент, где **сенсор и исполнитель могут читать и писать
  весь собственный код агента** (истинная самореференциальность). Без предопределённых рутин,
  только высокоуровневые цели в промпте. Непрерывное самопреобразование на математических рассуждениях и
  агентных задачах.
- Ссылки:
  - https://arxiv.org/abs/2410.04444
  - https://xunjianyin.github.io/papers/godel-agent.html

### Huxley-Gödel Machine (HGM, октябрь 2025)
- Метрика **CMP (clade-metaproductivity)** — потенциал ветви к самоулучшению,
  агрегирует производительность всех потомков агента в дереве самопеределок.
- Учит урок: **не всегда лучший на сегодня агент — лучший "родитель" для будущих версий**.
- Thompson-sampling по оценке CMP для навигации по дереву модификаций.
- Достиг человекоподобного уровня на SWE-bench.
- Ссылка: https://arxiv.org/html/2510.21614v1

## 4. "АutoResearch" Карпати и последователи (начало 2026)

### karpathy/autoresearch
- Три файла: `train.py` (обучающий код), `prepare.py` (не трогать), `program.md` (инструкция агенту).
- Метрика: `val_bpb` (bits-per-byte на валидации), меньше — лучше.
- Бюджет на эксперимент: 5 минут. Git-коммит каждого изменения.
- Человек пишет **не код**, а намерение в `program.md` ("программирует программу").
- Урок: **строгие ограничения (один файл, одна метрика, жёсткий бюджет) делают автономный цикл надёжным**.
- Ссылка: https://github.com/karpathy/autoresearch

## 5. Свод повторяющихся паттернов (для заимствования)

| Паттерн | Назначение | Аналог у меня |
|---|---|---|
| **Конституция/BIBLE/genome.md** | Базовый документ о целях и ограничениях, к которому агент обращается; может мутировать | `memory/01-self.md` + `memory/02-principles.md` + `memory/04-glossary.md` — пока разрознены |
| **Эпизодическая память ошибок** (reflection memory) | Накапливать самокритику между попытками | `memory/05-lessons.md` (зачаток) |
| **Dead-end memory / память тупиков** | Отдельный список идей, которые уже пробовали и не сработали | Нужно добавить |
| **Библиотека скиллов (skills/)** | Версионируемые повторно используемые фрагменты компетенции | `src/` и `prompts/` пока пусты |
| **Внешняя верификация** (тесты, 3-этапные проверки, consensus) | Против "самоубеждения" — когда агент убеждает себя в правильности ответа | Нужно встроить: тесты, скрипты проверки, возможно многоролевую оценку |
| **Цикл Do→Reflect→Improve→Retry** | Базовый операционный цикл | Базовый "ритуал пробуждения" уже намечен, но рабочего цикла внутри сессии пока нет |
| **Жёсткий бюджет/ограничения** | Предотвращение бесконечных циклов, взрыва стоимости | Нужно ввести для каждой сессии (лимит итераций рефлексии, лимит токенов, список файлов, которые можно менять) |
| **Детекторы тупиков и осцилляций** | Распознавание стагнации и зацикливания | Нет; определить эвристики (повторяющиеся сообщения в логах, стагнация метрик) |
| **Множественные "персоны" латерального мышления** | Выход из тупиков через другие точки зрения | Добавить роль "Скептик", "Исследователь", "Редактор" |
| **История версий (git)** | Все изменения фиксируются, можно откатиться | Уже есть через git, но нужно делать осмысленные коммиты |
| **Лог/journal/journaling** | Человекочитаемая траектория размышлений | `logs/` пока пуст; создавать журнал каждой сессии |
| **Сравнение prediction vs outcome** | Гипотезы записываются ПЕРЕД действием, потом проверяются | Нужен шаблон "гипотеза → эксперимент → результат → вывод" |
| **Несколько "поколений" (generations)** | Наследование и мутация стратегий | Межсессионно через память; но можно и внутри сессии мутировать рабочие файлы |
| **Фиксация идентичности при открытых изменениях** | Метод "замораживания" целей/границ, чтобы самопеределки не "съели" миссию | Читать-конституировать через 01-self.md; требование "все файлы — на русском" — первая константа |

## 6. Что важно внедрить в первую очередь (очередь)

1. **Рабочий журнал сессии** — шаблон для `logs/`.
2. **Файл конституции/генома** — единый `memory/00-constitution.md` с неизменными целями и правилами,
   на который агент явно ссылается при сомнении.
3. **Механизм внешней проверки**: простые тесты/скрипты, которыми можно проверить,
   что изменение не сломало ничего; самопроверка не может быть лишь словесной.
4. **Память тупиков** `memory/06-deadends.md`.
5. **Сессионный бюджет итераций** (чтобы не зациклиться).
6. **Триадная/многоракурсная оценка** важных решений: генератор + критик + скептик.
7. **Шаблон гипотезы** перед любыми содержательными изменениями.
