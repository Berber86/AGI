# Infinite Forge — Рождение цивилизаций

Infinite Forge — браузерный карточный прототип о становлении цивилизаций. Основной интерфейс теперь работает на React/Vite и использует тёплую графику нового редизайна; локальная кампания включает процедурную карту 7×7, экономику, развитие, кузницу и тактические бои. Это прототип, а не общий сетевой мир или MMO-сервер.

## Запуск

Нужен Node.js 20.19+ (или 22.12+).

```bash
npm ci
npm run dev
```

Vite напечатает адрес локального приложения. Production-сборка и предпросмотр:

```bash
npm run build
npm run preview
```

Прежний standalone-интерфейс сохранён в [`legacy.html`](legacy.html). Он использует ту же кампанийную модель и карту, что и React-приложение. Сборка копирует legacy-страницу, скрипты и ресурсы в `dist/legacy.html`.

## Кампания и карта

Новая кампания получает **ровно 49 клеток в сетке 7×7**, центральная `tile-3-3` — старт. Локальный seed-генератор создаёт рельеф, воду, реку, месторождения и поселения соседей; у клеток есть собственные названия и содержательные описания из шаблонов. Генерация карты не вызывает LLM. Около половины пустых пригодных для освоения участков защищены локальными квестовыми отрядами: победа в тактическом бою снимает охрану и передаёт клетку игроку. Туман войны показывает области в радиусе двух шагов по четырём сторонам от принадлежащих земель; неизвестные клетки не раскрывают содержимое. Захват и экспедиции возможны только в соседних по стороне областях.

`campaign-map.js` отделяет генератор карты от интерфейса. Игровая модель в `campaign.js` используется и legacy-страницей, и React-адаптером `src/game/model.js`; состояние карты и территорий хранится в кампании v4 под ключом `iforge_campaign_v4`.

Запасы ресурсов хранятся дробно: доход `0.7` в день от одного работника накапливается, а округление происходит только при отображении (склад и чипы показывают целые, отчёт дня — дельты с одним знаком после запятой). В бою базовый лимит колоды — `4` карты (пустые места добираются ополчением), военные постройки добавляют слоты до `6`; усталость за пустую колоду начинается с `6`-го хода и нарастает с каждой попыткой добора. Журнал боя ведётся грамотно по сторонам («Вы тянете/выводите», «Враг тянет/выводит»), а у вражеского ополчения собственные названия отрядов — «Племенные копейщики атакует „Племенные копейщики"» больше не встречается. Панель «Свод правил» в поселении и подписи на чипах раскрывают пороги роста народа, мягкий кап склада, цены походов и порог усталости.

Реестр эффектов (`campaign.js → EFFECTS`) прошёл ревизию механики: советник предлагает только эффекты с реальным потребителем в игровом коде — список экспортируется как `GENERATIVE_EFFECTS` (метки `hidden` оставлены в реестре ради старых сейвов). Добавлены эффекты, которые генератор раньше продать не мог: `fatigue_resist` (+1 ход до усталости — сдвигает порог из `b.turn < 6` в движке боя на сторону игрока), `active_building_slots` (капительная постройка открывает пятый слот активных зданий) и `craft_quality` (+1 к качеству ковки в цене заказа кузницы). Подпись торгового бонуса теперь честно перечисляет дельты (`+0.3🪵` и `+0.2📚`).
Сохранения v2/v3 мигрируют на новую карту **без переноса прежних владений**. Ресурсы, эпоха, прогресс, коллекционные карты и выбранная колода сохраняются; старые ключи не удаляются. Коллекция карт и настройки API остаются в отдельных ключах `localStorage`.

Региональные действия, здания, доход, квестовые бои и экспедиции работают на процедурных клетках. Неохраняемый нейтральный участок стоит `2` провизии + `2` материала; квест за охраняемую клетку и экспедиция к соседнему поселению стоят `4` провизии + `2` материала. Поражение оставляет нейтральную клетку неосвоенной или поселение соседу; отряд возвращает половину припасов (`2` провизии), материалы и AP не восстанавливаются. Перед квестовым боем панель клетки показывает разведку — грубую оценку сил охраны относительно вашего отряда. Рядом со стартовым поселением всегда есть хотя бы одна земля без охраны, чтобы обучающий шаг заселения выполнялся во всех мирах. Само владение клеткой дохода не даёт — он появляется после постройки регионального здания. Прототип карты не является общей MMO-картой; сервер, сеть и синхронизация здесь не реализуются.

## Первый вход и первые шаги

1. Игрок ничего не пишет: он выбирает имя народа, происхождение и **замысел** — готовую фразу о том, чем этот народ живёт (6 вариантов). Единственное поле ввода — API-ключ.
2. Затем обязательный шаг: Hydra API-ключ. Он проверяется запросом к провайдеру, и без рабочего ключа игра не начинается — в проекте не осталось заранее записанных наук, построек и замыслов.
3. Советник читает выбранный замысел, землю, черту и наследие народа и создаёт **первое дело**: свою науку и связанную с ней постройку. Готового списка вариантов нет, проект создаётся один раз для конкретного народа.
4. После этого игрок видит созданное дело и попадает на экран, где находится следующий шаг наставника. Верхняя полоса «Наставник» ведёт по маршруту: изучить первое дело → построить здание → занять соседнюю область → сыграть тренировочный бой. Первые шаги можно пропустить одной кнопкой.
5. Пока маршрут не пройден, «Поселение» и «Развитие» показывают одну задачу вместо полного набора панелей, а на карте подсвечены соседние клетки. Дальше открывается обычный интерфейс со всеми экранами.

## Кузница и советники

1. В кузнице выберите замысел военного советника, качество сырья и время работы. Свободного текстового промпта нет; научный советник сам читает затравку, эпоху, земли и запасы и предлагает три разных проекта — хозяйство, защиту и знания.
2. Перед заказом показываются цена и шанс редкости. Обычная карта использует `gpt-6-luna`, необычная и редкая — `glm-5.2`; игровые характеристики валидируются по технической схеме, без общего бюджета силы.
3. Ресурсы списываются заранее. Тщательная и мастерская ковка занимают 1 или 2 кампанийных дня. Если модель недоступна или ответ не прошёл проверку, стоимость возвращается.
4. Карты сохраняются в коллекции; боевые экземпляры — копии для матча.

API-ключ хранится в `localStorage` текущего браузера и отправляется напрямую на `https://api.hydraai.ru/v1/chat/completions`. Не вводите личный ключ на общем или недоверенном устройстве. Прежний standalone-интерфейс (`legacy.html`) остаётся доступен из настроек и по-прежнему использует локальные заготовки — он не является основным входом в игру.

## Проверки

```bash
npm test
npm run typecheck
npm run build
node tools/economy-sim.js
```

Тесты проверяют боевую модель, 49-клеточную генерацию на множестве seed, размещение охраны, радиус видимости, маскирование карты, центральный старт, четырёхстороннее соседство, миграцию сохранений, территориальные действия, совместимость React-модели с legacy-кампанией, а также новый вход: затравка, первый проект только от модели, обязательный ключ и маршрут наставника. Симулятор экономики учитывает стоимость победных квестовых боёв и использует фиксированный seed и динамические ID клеток; сценарии диагностические, не целевой баланс.

## Устройство проекта

```text
index.html                         React/Vite-приложение и точка входа
src/pages/                          экраны первого входа, поселения, карты, развития, кузницы, армии и боя
src/game/model.js                   адаптер к общей кампанийной модели
src/game/cards.ts                   карты, локальные/LLM-советники и валидация эффектов
src/game/battle.ts                  тактический движок React-интерфейса
campaign-map.js                    локальный генератор карты 7×7 и тексты клеток
campaign.js                        общая модель кампании и legacy-интерфейса
legacy.html                        прежний standalone-интерфейс на той же карте
campaign.css                       стили legacy-интерфейса
/tests/                             регрессии игры, карты и миграции
/tools/copy-legacy.mjs              включает legacy-страницу и ресурсы в production-сборку
tools/economy-sim.js                повторяемый сценарный прогон экономики
```

Общее MMO-хранилище, аккаунты, торговля, дипломатия, серверные тики и сетевые осады остаются вне этого прототипа.
