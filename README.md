# Infinite Forge — Рождение цивилизаций

Infinite Forge — браузерный карточный прототип о становлении цивилизаций. Основной интерфейс теперь работает на React/Vite и использует тёплую графику нового редизайна; локальная кампания включает процедурную карту 7×7, экономику, развитие, кузницу и тактические бои. Это прототип, а не общий сетевой мир или MMO-сервер.

## Запуск

Нужен Node.js 20.19+ (или 22.12+).

```bash
npm ci
npm run dev
```

Vite напечатает адрес локального приложения. Production-сборка и предпросмотр:

```bash
npm run build
npm run preview
```

Прежний standalone-интерфейс сохранён в [`legacy.html`](legacy.html). Он использует ту же кампанийную модель и карту, что и React-приложение. Сборка копирует legacy-страницу, скрипты и ресурсы в `dist/legacy.html`.

## Кампания и карта

Новая кампания получает **ровно 49 клеток в сетке 7×7**, центральная `tile-3-3` — старт. Локальный seed-генератор создаёт рельеф, воду, реку, месторождения и поселения соседей; у клеток есть собственные названия и содержательные описания из шаблонов. Генерация карты не вызывает LLM. Около половины пустых пригодных для освоения участков защищены локальными квестовыми отрядами: победа в тактическом бою снимает охрану и передаёт клетку игроку. Туман войны показывает области в радиусе двух шагов по четырём сторонам от принадлежащих земель; неизвестные клетки не раскрывают содержимое. Захват и экспедиции возможны только в соседних по стороне областях.

`campaign-map.js` отделяет генератор карты от интерфейса. Игровая модель в `campaign.js` используется и legacy-страницей, и React-адаптером `src/game/model.js`; состояние карты и территорий хранится в кампании v4 под ключом `iforge_campaign_v4`.

Запасы ресурсов хранятся дробно: доход `0.7` в день от одного работника накапливается, а округление происходит только при отображении (склад и чипы показывают целые, отчёт дня — дельты с одним знаком после запятой). В бою базовый лимит колоды — `4` карты (пустые места добираются ополчением), военные постройки добавляют слоты до `6`; усталость за пустую колоду начинается с `6`-го хода и нарастает с каждой попыткой добора. Журнал боя ведётся грамотно по сторонам («Вы тянете/выводите», «Враг тянет/выводит»), а у вражеского ополчения собственные названия отрядов — «Племенные копейщики атакует „Племенные копейщики"» больше не встречается. Панель «Свод правил» в поселении и подписи на чипах раскрывают пороги роста народа, мягкий кап склада, цены походов и порог усталости.

**Духовность (🙏, ключ `faith`) — четвёртый ресурс** наряду с 🌾 🪵 📚. Один клан-жрец даёт `0.6🙏` в день (`WORKER_BASE_YIELD.faith`), здания советника с эффектом `income_faith` (категория `religion`, максимум 2 пункта) добавляют `+0.5🙏` с каждого клана за пункт, а региональные святилища дают фиксированный доход: «Место наблюдений и святилище» — `+2📚 +1🙏`, «Форпост и капище» — по `+1` всех четырёх ресурсов. При нехватке населения кланы снимаются в порядке `idle → faith → knowledge → materials → food`: голод лишает народ сначала молитвы, а не хлеба. Склад общий для всех ресурсов и растёт на `+5` за каждую эпоху (`STORAGE_PER_ERA`): без этого излишек сверх базового склада 15 таял бы вдвое, запас упирался в «склад + дневной доход» (~20 📚) и поздние пороги просветления стали бы недостижимы физически.

Реестр эффектов (`campaign.js → EFFECTS`) прошёл ревизию механики: советник предлагает только эффекты с реальным потребителем в игровом коде — список экспортируется как `GENERATIVE_EFFECTS` (метки `hidden` оставлены в реестре ради старых сейвов). Добавлены эффекты, которые генератор раньше продать не мог: `fatigue_resist` (+1 ход до усталости — сдвигает порог из `b.turn < 6` в движке боя на сторону игрока), `active_building_slots` (капительная постройка открывает пятый слот активных зданий) и `craft_quality` (+1 к качеству ковки в цене заказа кузницы). Подпись торгового бонуса теперь честно перечисляет дельты (`+0.3🪵` и `+0.2📚`).
Сохранения v2/v3 мигрируют на новую карту **без переноса прежних владений**. Ресурсы, эпоха, прогресс, коллекционные карты и выбранная колода сохраняются; старые ключи не удаляются. Коллекция карт и настройки API остаются в отдельных ключах `localStorage`.

Шкала эпох в игре одна, и источник истины — `const ERAS`: 0 Каменный век, 1 Античный мир, 2 Средневековье, 3 Ренессанс, 4 Эпоха Пара и Стали 1800-1910, 5 Новейшее время, 6 Будущее 2050-2150. По этим индексам живут исторический контекст эпохи (`ERA_HISTORICAL`), ключевые ресурсы (`ERA_KEY_RESOURCE`: обсидиан → бронза → железо на эпохах 0/1/2), месторождения карты (`BRONZE_SITE_MIN_ERA = 1`, `IRON_SITE_MIN_ERA = 2`, `GUARD_ERA_CAP = 2`), ветви науки (`SCIENCE_BRANCHES.minEra`) и бронзовый тег карт (`BRONZE_CARD_MIN_ERA = 1`, у игрока и у врага одинаково). Поле `era` у карты остаётся боевым тегом `ancient | bronze`, а реальная эпоха кампании уходит в промпт кузнеца текстом — вместе с описанием эпохи, её народами и технологиями.
Эпоху открывает **просветление народа**, а не число изученных наук. В конце дня считается `2·📚 + 1·🙏` против порога эпохи `36 + 8·era` (36/44/52/60/68/76/84): книга весит вдвое молитвы. Порог берётся по текущему запасу, за день случается не больше одного перехода, а в переходе половина 📚 и 🙏 сгорает («собор и жертва»). Порог намеренно выше любого стартового запаса (14–20 очков дают 6–9 📚 и 2 🙏), а **первый день эпоху не открывает ни при каком запасе** (`ERA_ENLIGHTENMENT_MIN_DAY`): раньше порог был 16, и пять происхождений из восьми получали Античный мир в конце первого же дня, ничего для этого не сделав. Теперь эпоху даёт накопленное трудом кланов, а не подаренное происхождением. Счётчик «науки до эпохи» удалён, науки остались способом получать здания и эффекты. Всё читается одной функцией `getEraProgress(state)` → `{score, threshold, remaining, ratio, ready, formula:'2·📚 + 1·🙏', weights, spendRatio, finalEra}` и показывается шкалой «Просветление эпохи» во вкладке «Развитие», строкой в отчёте дня и полосой сезона в legacy-экране; на последней эпохе `finalEra: true` и перехода нет. Темп замерен симулятором: при стартовом распределении кланов (2 земледельца, добытчик, книжник, жрец) и полном бездействии эпоха 1 наступает на 12-й день, эпоха 2 — на 25-й; если посадить кланы на книги (3 земледельца и 2 книжника), эпоха 1 приходит на 7-й день, эпоха 2 — на 14-й, эпоха 3 — на 21-й, эпоха 4 — на 29-й; абсолютный предел (весь народ на книгах при знаниевой черте и наследии, пусть и в голод) — эпоха 1 уже на 3-й день. Одной духовностью эпоху не взять: мягкий склад держит 🙏 около «склад + дневной доход», поэтому книга обязательна, а молитва ускоряет. Кланам в простое просветление не начисляется, так что эпоха — это всегда производство. Удержать эпоху можно только расходом 📚 и 🙏 (науки, постройки, ковка, миссии), а цена ковки растёт как `1 + 0.4·era` — поздние эпохи делают её ощутимой.

**Духовность тратится ровно на одно — миссию «слово народа»**: присоединить нейтральную клетку без боя и **без требования соседства** за `5 + 2·era` 🙏, а охраняемую — обратить за `12 + 5·era` 🙏: отряд принимает веру и уходит, клетка становится вашей без сражения, а `guard` остаётся в описании клетки (мир не переписывается). Миссия стоит 1 AP и собственный дневной приказ `mission` (лимит — `getOrderCapacity`, как у прочих приказов). Слово не доходит до воды, до тумана войны, до собственной земли, до чужого поселения («только экспедицией») и до клеток, закрытых по эпохе (`minEra`). Ковка, захват, экспедиция и указы духовность не стоят: расход у ресурса один, поэтому он не размывает остальную экономику. В интерфейсе миссия — отдельная кнопка рядом с основным действием клетки (`missionRegion`), доступные только словом клетки подсвечены на карте, а состояние всегда можно прочитать чистым `getMissionState(state, tileId)`.

При переходе эпохи наследие больше не меняется само: игрок выбирает одну из культур новой эпохи (до трёх кандидатов) или сохраняет прежнюю — в обоих случаях технологии эпохи уже доступны, потому что все гейты читают `player.era`, а не культуру. Выбор живёт в модели (`getCultureChoice` / `chooseCulture`) и показывается сразу после отчёта дня **модальным окном** (`CultureChoiceModal`): три кандидата эпохи и «оставить своё наследие», окно нельзя закрыть, не выбрав. Незакрытый выбор больше не остаётся незамеченным: если игрок зашёл с сохранения, где окно было пропущено, в «Развитии» сама открывается вкладка «Наследие», точка-индикатор стоит на разделе, а панель «Линия культур» в хронике напоминает о решении, а в standalone-странице выбор рисует панель `renderCultureChoice`. Миры, созданные до выравнивания шкалы, сохраняют прежние `minEra` клеток: версии мира и кампании не менялись, поэтому на старом мире редкая ковка в «Античном мире» может упереться в медь и олово, которые карта откроет только с эпохи 2; лечится это стартом нового мира. Разбор рассинхрона, таблицы по эпохам и список проверок — в [`docs/ERA_LADDER_ALIGNMENT_RESULT.md`](docs/ERA_LADDER_ALIGNMENT_RESULT.md).

Региональные действия, здания, доход, квестовые бои и экспедиции работают на процедурных клетках. Неохраняемый нейтральный участок стоит `2` провизии + `2` материала; квест за охраняемую клетку и экспедиция к соседнему поселению стоят `4` провизии + `2` материала. Поражение оставляет нейтральную клетку неосвоенной или поселение соседу; отряд возвращает половину припасов (`2` провизии), материалы и AP не восстанавливаются. Перед квестовым боем панель клетки показывает разведку — грубую оценку сил охраны относительно вашего отряда. После захвата или присоединения новой клетки современный React-интерфейс просит советника придумать **три разные региональные постройки** под конкретную местность, биом, ресурс, географию народа, культурное наследие и текущую эпоху. Игрок выбирает одну: она заменяет стандартное здание клетки, строится за обычную цену участка и даёт придуманный моделью прямой ежедневный доход ресурсами. Варианты и выбранный проект хранятся в сохранении клетки; эффекты ограничены поддерживаемым региональным набором и проходят проверку модели. Отдельный `legacy.html` оставлен как старый standalone-интерфейс: он показывает и строит уже сохранённые чертежи, но генерация новых клеточных вариантов доступна в основном React-интерфейсе. Привязанные к месторождениям ключевые ресурсы эпохи (обсидиан, медь/олово, железо) по-прежнему открываются после постройки на соответствующей клетке. Владение само по себе дохода не даёт — он начинается после строительства. Прототип карты не является общей MMO-картой; сервер, сеть и синхронизация здесь не реализуются.

## Первый вход и первые шаги

1. Онбординг — это **три выбора и ничего больше**: **происхождение** (земля, биом и стартовый запас), **наследие** — одна из шести культур Каменного века (Ямная, Триполье-Кукутени, Чатал-Хююк, Натуф, Дзёмон, Гёбекли-Тепе) с датами, местом, сутью и бонусами, и **замысел** — менталитет народа (5 вариантов). Игрок ничего не пишет руками: ни имени, ни промпта.
2. **Шага «Имя народа» больше нет.** Имя происходит из выбранной земли (`ORIGINS.people`, `originPeopleName()`): «Люди Великой Реки», «Каменщики Предгорий», «Лесные Земледельцы», «Дети Ямной Степи», «Береговые Мореходы», «Хранители Колодцев». Генератор имён с перебросами удалён — он давал сочетания вроде «Стада Солёной Тропы», которые спорили с серьёзным тоном наследия, а в одиночной игре этап ничего не решал. Имя видно в карточке земли и в сводке перед основанием; standalone-страница по-прежнему принимает своё имя (там поле осталось в модели, но из формы убрано).
3. **Происхождение и замысел переписаны в одном тоне с наследием**: шесть земель вместо восьми и пять замыслов вместо шести, у каждого — датированный археологический прототип (`historical` у земли, `note` у замысла), развёрнутое описание и то, чего эта земля от народа требует. Замысел теперь формулируется как мировоззрение («Небо над нами — свод законов: по нему мы знаем время сева и обряда»), а не как профессия («Мы торговцы соли»). Бонусы и `id` сохранены, поэтому старые сохранения и симулятор экономики не поехали; земли `oasis` и `marsh` и замысел `trade` убраны — у сохранений с ними `originId`/`seedChoiceId` обнулятся при нормализации, как и при других правках списков.
4. **Выбор модели упразднён.** Модель выбирает игра, а не игрок: `ADVISOR_MODEL = "gpt-6-luna"` отвечает за науки, советы, имена построек и обычные карты, а кузница сама отдаёт необычные и редкие карты `glm-5.2` (`cardCraftQuote.modelByRarity`). Шага «Советник» в онбординге и выпадающего списка в настройках больше нет (`MODEL_GROUPS`/`setModel` удалены, старый ключ `iforge_model` стирается при запуске). Ключ ИИ по-прежнему живёт только на сервере.
5. **Народ основывается сразу.** `foundCampaignState()` (в React-сторе `foundPeople`) завершает онбординг тремя выборами: игрок попадает в поселение первого дня с пустым кодексом и без построек. Экрана «выбери науку и здание» на старте больше нет — он не вызывается сам и не требует LLM до первого клика.
6. **Наука спрашивается одним вызовом и только по клику игрока** («Развитие» → «Наука» → «Спросить советника»): советник читает замысел, происхождение, землю, черту, наследие, запасы и эпоху и предлагает **три разные науки**, у каждой — своё здание и **свой набор свойств**. Промежуточный шаг «о чём будет наука» (превью направлений) и второй вызов «советника-строителя» удалены: содержательную работу делал первый вызов, а второй возвращал три здания, неотличимых по эффектам. `llmScienceOffers` теперь отбраковывает совпадения не только по названиям наук и зданий, но и по подписи наборов эффектов, и требует ровно три варианта. Подпись «Почему вашему народу…» убрана из промпта и из интерфейса: поле `rationale` у научных проектов больше не запрашивается и не показывается.
7. Воинская доктрина `unit_power` по-прежнему не предлагается, пока народ не освоил ключевой ресурс эпохи (`hasEraKeyResource`): в Каменном веке это обсидиановая мастерская, поэтому первый чертёж не может оказаться непостроенным.
8. Принятая наука ложится в кодекс чертежом: её нужно изучить (1🌾 + 1📚), а здание — возвести отдельным приказом (3🪵). Никакого обязательного маршрута: обучение-наставник удалено, весь интерфейс открыт сразу — наука, здания, карта, кузница, армия. Что и в каком порядке делать, решает сам игрок; единственная подсказка — карточка «Что дальше» в поселении.
9. Единственная мягкая уступка новичку — **первый бой**: он проходит без построек у врага и с полной энергией на выходе, с подсказками тренера. Это обычная тренировка: играть её не обязательно, на ресурсы и границы она не влияет.

## Кузница и советники

1. В кузнице выберите замысел военного советника, качество сырья и время работы. Свободного текстового промпта нет. Научный советник работает в один шаг: три разные науки с тремя разными зданиями и тремя разными наборами свойств. Готовых ветвей в React-интерфейсе нет; заготовленный список `SCIENCE_BRANCHES`, словарь тем `SCIENCE_DIRECTION_THEMES` и двухшаговые превью направлений остались только запасным оффлайн-путём standalone-страницы.
2. Перед заказом показываются цена и шанс редкости. Обычная карта использует `gpt-6-luna`, необычная и редкая — `glm-5.2`; игровые характеристики валидируются по технической схеме, без общего бюджета силы.
3. Ресурсы списываются заранее. Тщательная и мастерская ковка занимают 1 или 2 кампанийных дня. Если модель недоступна или ответ не прошёл проверку, стоимость возвращается.
4. Каждая карта получает **историческую справку** — блок `history` (`title` + `text`), который кузнец пишет в тот же вызов и привязывает к **эпохе кампании и наследию народа**: из чего и какими технологиями эпохи это делали, кем были эти люди, чем это было в быту и почему карта бьётся именно так (её числа и ключевые слова). Справка лежит в самой карте, показывается аккордеоном на лицевой стороне (в коллекции, в окне выкованной карты — сразу раскрытой, при осмотре в бою) и подписана эпохой и наследием. Справку пишет только модель: если она её не вернула, блока у карты нет — локальных заготовок намеренно не делаем, иначе «древний мир» и «античность» снова станут одинаковыми.
5. Карты сохраняются в коллекции; боевые экземпляры — копии для матча.

## Ключ Hydra: только через переменную окружения сервера

Ключ `HYDRA_API_KEY` больше нигде не вводится в интерфейсе — ни на онбординге, ни в настройках. Он задаётся один раз на сервере:

- **Vercel**: Project Settings → Environment Variables → добавить `HYDRA_API_KEY` со значением ключа (Production/Preview/Development — по необходимости), затем передеплоить проект. Serverless-функция [`api/hydra.js`](api/hydra.js) читает эту переменную и проксирует запросы к `https://api.hydraai.ru/v1/chat/completions`, подставляя `Authorization` сама — браузер ключ никогда не видит.
- **Локальная разработка**: положите `HYDRA_API_KEY=...` в `.env` в корне проекта (файл не коммитится) или экспортируйте переменную окружения перед `npm run dev`/`npm run preview`. `vite.config.ts` поднимает тот же прокси по пути `/api/hydra` для локального сервера, так что клиентский код (`src/game/cards.ts`) всегда стучится по одному относительному адресу и в проде, и локально.

Если переменная не задана, `/api/hydra` отвечает понятной ошибкой («Сервер не настроен: переменная окружения HYDRA_API_KEY не задана…»), а статус «ИИ» в «Настройках» показывает это игроку без необходимости что-либо вводить. Прежний standalone-интерфейс (`legacy.html`) остаётся доступен из настроек и по-прежнему использует локальные заготовки — он не является основным входом в игру и этот прокси не использует.
