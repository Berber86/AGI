# Infinite Forge — Рождение цивилизаций

Infinite Forge — браузерный карточный прототип для проверки систем будущей MMO о становлении цивилизаций. В проект интегрирован новый React-интерфейс: локальная кампания с экономикой, семь регионов, LLM-советники, кузница постоянных карт и тактические бои. Прежний standalone-интерфейс сохранён отдельно в `legacy.html`. **Это локальная вертикальная вырезка, не общий сетевой мир или MMO-сервер.**

## Запуск

Новый интерфейс собран на React, Vite и Tailwind CSS. Нужен Node.js 20.19+ (или 22.12+):

```bash
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно <http://localhost:5173>). Production-сборка и локальный предпросмотр:

```bash
npm run build
npm run preview
```

Старая самостоятельная версия сохранена в [`legacy.html`](legacy.html); её можно открыть напрямую через Vite или обычный статический сервер. Сборка также копирует её, боевой движок и нужные ресурсы в `dist/legacy.html`.

## Кузница и советники

1. При первом запуске пройдите мастер основания цивилизации: имя народа, происхождение и первое направление развития.
2. В **Настройках** при желании укажите Hydra API-ключ и модель для науки и советов. Ключ необязателен: без него приложение предлагает локальные идеи и создаёт локальные карты.
3. В **Кузнице** выберите один из замыслов военного советника, качество сырья и время работы. Свободного текстового промпта нет. У научного советника игрок выбирает только широкую ветвь; конкретные проекты учитывают эпоху, земли и запасы.
4. До подтверждения показываются шанс редкости и цена. Редкость выпадает до LLM-запроса: обычная карта использует `gpt-6-luna`, необычная и редкая — `glm-5.2`. Статы, боевые цены, ключевые слова и допустимые DSL-эффекты задаёт генератор; валидные сильные или странные карты не ослабляются ради power-budget.
5. Ресурсы списываются заранее. «Тщательная» и «мастерская» ковка занимают 1 или 2 кампанийных дня и требуют дополнительных материалов. Если модель недоступна или её ответ не проходит техническую схему, стоимость возвращается.
6. Быстрый результат можно сразу добавить в коллекцию. Длительный заказ виден в очереди; после срока его можно забрать. Полученная карта остаётся в коллекции — гибель её боевой копии не уничтожает карточку.

Таблица вероятностей и цены — **начальные значения локального прототипа**, а не утверждённый MMO-баланс. Ключ хранится в `localStorage` текущего браузера и отправляется напрямую на `https://api.hydraai.ru/v1/chat/completions`. Не вводите личный ключ на общем или недоверенном устройстве.

## Проверки

В корне проекта:

```bash
npm test
npm run typecheck
npm run build
```

`tests/effects.test.js` и `tests/battle-turn.test.js` проверяют сохранённую версию `legacy.html`; `tests/campaign.test.js` проверяет общую модель кампании: территориальный контроль, доход, захват после боя, гейты качества сырья, оплату ковки и восстановление незавершённых действий. `campaign.js` и новая `src/game/model.js` используют один формат кампанийных сохранений (`iforge_campaign_v3`), а коллекция и Hydra API-ключ остаются в прежних `localStorage`-ключах.

Для повторяемой проверки темпа экономики запустите `node tools/economy-sim.js`. Сценарии сравнивают бездействие, ковку, освоение металлов с оплатой исследований/территорий, цикл «исследование → строительство» и путь «месторождения → условная победа в экспедиции → редкая карта». Это диагностические сценарии, а не целевой баланс; победа в симуляции задана вручную, а не рассчитывается боевым ИИ.

## Что уже работает

- **Тактический бой:** новый интерфейс использует отдельный движок в `src/game/battle.ts`; прежний inline-движок оставлен в `legacy.html` и покрыт регрессионными тестами. Карточные статы поддерживают намеренно широкий диапазон результатов.
- **LLM-карты:** полные характеристики, боевые цены, keywords, описание и DSL-эффекты создаются моделью. Валидатор ограничивает только техническую исполнимость; общего бюджета силы и обязательного штрафа нет.
- **Советники как посредники:** для ковки игрок задаёт готовый тип/направление и вложения; в науке — только одну широкую ветвь. Научный советник сам учитывает эпоху, земли и запасы, предлагая читаемый ситуационный вариант вместо ещё нескольких полей настройки. Свободный текст в prompt не вставляется.
- **Редкость и экономика ковки:** обычная/необычная/редкая редкость зависит от оплаченного качества сырья, опыта кузнеца и времени. Шансы, расходы и очередь связаны с ресурсами и днями локальной кампании.
- **Постоянная коллекция:** созданная карта после получения остаётся карточкой игрока; боевые экземпляры — копии для матча.
- **Старт кампании:** выбор происхождения, первого научного направления и стартовой колоды. Необязательный маршрут первой сессии ведёт через исследование, строительство, захват соседнего ресурса и тренировочный бой; он не блокирует игру и не выдаёт отдельную награду.
- **Локальная стратегическая карта:** семь связанных узлов — дом, пойма, холмы, круг времён года, медный рудник, оловянный путь и поселение соперника. Нейтральные узлы требуют соседства, ресурсов и дневного приказа; контроль даёт доход. Медь открывает отборное сырьё, медь вместе с оловом — мастерское. Экспедиция стоит припасы и приказ; победа переносит владение, поражение оставляет регион защитнику.
- **Локальная кампания:** провизия/материалы/знания, научные проекты, постройки, активные слоты зданий, эпохи, ручное продвижение дня и тестовые ИИ-соседи. Это ускоренная 30-дневная песочница: полный проход семи эпох за сезон допустим и намеренно не замедляется. Тренировочные бои остаются бесплатными; только территориальная экспедиция меняет владение.
- **Коллекция и армия:** поиск/фильтры, сохранение карт в браузере и размер колоды, зависящий от развития цивилизации; незаполненные боевые слоты занимают карты ополчения. Прежний 10-карточный standalone-режим доступен через `legacy.html`.

## Что пока не реализовано

- Нет большого общего мира, территорий игроков/кланов, торговли, дипломатии, тумана войны, осад/обороны в отсутствие игрока и серверных тиков. Текущие семь узлов — фиксированная локальная тестовая карта.
- Нет аккаунтов, серверных сохранений, общего мира, сетевого мультиплеера и кланового рейтинга; клиентский `localStorage` не является авторитетным MMO-хранилищем.
- ИИ-соседи остаются локальными заглушками. Экспедиция проверяет только один захват против ИИ; противник не расширяется и не управляет территориями, а результат боя вручную не симулируется экономическим тестом.
- Научные эффекты используют существующую ограниченную схему кампании; это не тот же свободный LLM-DSL, что у боевых карт.

Исходное задание сохранено в [`docs/STRATEGIC_CIVILIZATION_AGENT_BRIEF.md`](docs/STRATEGIC_CIVILIZATION_AGENT_BRIEF.md), но оно предшествует текущему локальному campaign MVP и местами устарело. Актуальное MMO-направление и следующие проектные задачи описаны в [`docs/STRATEGIC_CIVILIZATION_DESIGN.md`](docs/STRATEGIC_CIVILIZATION_DESIGN.md).

## Устройство проекта

```text
index.html                         React/Vite-приложение и точка входа
src/pages/                          экраны поселения, карты, развития, кузницы, армии и боя
src/game/model.js                   чистая модель кампании; тот же формат сохранений, что campaign.js
src/game/cards.ts                   карточки, локальные и LLM-советники, валидация DSL
src/game/battle.ts                  тактический движок нового интерфейса
legacy.html                         прежний standalone-интерфейс, оставленный для совместимости
campaign.js / campaign.css          прежняя кампания и её стили, используются legacy.html
tribes-legacy.html                  отдельная старая версия Tribes
assets/ и images/                   графика приложения
/tests/                             регрессии кампании и сохранённого legacy-движка
tools/copy-legacy.mjs               включает прежний интерфейс в production-сборку
tools/economy-sim.js                повторяемый сценарный прогон экономики
```

Новый интерфейс собирается Vite. Старый HTML сохранён без замены его боевого и кампанийного кода; он продолжает обслуживаться отдельно, а соответствующие регрессионные тесты читают `legacy.html`.
